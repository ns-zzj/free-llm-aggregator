## 恢复可用：提供商那个改成批量文案 + 模型上加一个（用户 2026-09-15 定）

用户原话：「那把提供商的搞成只要有一个不能用就显示"全部恢复可用"，模型那里再加个按钮。不过先记着待办，先不干。」

背景：状态本来就是模型级的（`source_state` 主键 `provider_id + model_id`），但提供商行上那个「恢复可用」
其实调的是 `POST /providers/:id/state` → `setStatusForProvider()`，**把该来源下所有模型一起清成 available**。
入口长在提供商行上、文案又只写「恢复可用」，容易以为是单个来源的范围；而且想手动恢复**某一个**模型时，
现在只剩下面两条路，都不理想：自动等冷却探测（要等 + 不一定过），或者模型行的「测试」（按真实调用处理，占速率额度、花钱）。

要做的两件（都在后台界面）：

1. **提供商行**（`public/app.js` 的 `providerRow()`）：
   - 显示条件从「聚合状态 ≠ available」改成 **只要该来源下有一个模型不是 available 就显示**
     （即 `modelsAvailable < modelsTotal`；后端 `/overview` 已经把这两个数算好了，见 `src/admin/routes.js` 的 `aggregateHealth()`）
   - 文案改成 **「全部恢复可用」**（点下去就是整家一起清，文案得说清范围）
2. **模型行加一个「恢复可用」按钮**：
   - 前端：模型管理表格（`renderModalModelList()` 里那个 `table(['对外模型名','上游 model id','图片','状态','操作'])`）
     的「操作」列，`state.status !== 'available'` 时才出现
   - 后端：加 `POST /providers/:id/models/:modelId/state`，内部用**已导出的** `sourceState.setStatus(providerId, modelId, 'available')`，十来行
   - 语义与「测试」互补：**测试 = 真跑一次、通过才恢复**；**恢复 = 我配置/额度已经修好了，别浪费一次真实请求**

这是逻辑改动，动手时先把 m6 / m8 里碰后台状态接口的用例看一眼。

## Gemini 原生格式（用户 2026-09-15 提，卡在没 key，先不动）

原话：「用这个协议的客户端太少了。我的 gemini 上游也没余额。先加进待办吧。不知道能不能做。」

**卡在哪**：不是"写不了"，是**没 key 没法验**。这个项目里每个适配器都是拿真 API 调出来的
（Cloudflare 的三种返回方言、Responses 缺字段被官方 SDK 静默丢事件、Anthropic 的 thinking 签名，全是实测才发现的），
盲写出来的适配器比没有更糟 —— 它看起来能用，等哪天填了 key 才发现对不上，还查不出是哪一层的问题。
**所以真要做的第一件事是拿到一个 key 做真机联调**（Google AI Studio 的免费 key 就行，不绑卡、跟 Vertex 的余额不是一回事），
或者找个愿意帮忙的第三方当真机验证者（**别开口借 key**，改成"我给你命令、你在你机器上跑、把原始响应贴回来"）。
在此之前这条不动。

先记结论，省得以后重新查：

- **上游**：`https://generativelanguage.googleapis.com/v1beta/openai/` 是 Google 官方的 OpenAI 兼容层。
  按我们现在"baseUrl 当完整前缀 + 只拼端点"的规矩，**它今天就能当 `openai-compatible` 用，一行代码都不用加**。
  所以「想用 Gemini 的额度」根本不缺这个适配器。
- **客户端**：只有 google-genai SDK（能改 baseUrl）和 Gemini CLI（靠社区 PR 才支持自定义地址）发原生格式。
  第三方工具基本不为它单独写一套 —— 这是它和 Anthropic 那份协议最大的区别。

真要做的两种（**是两件不同的事，别混**）：

1. **上游适配器 `gemini`**（便宜，照 `anthropic.js` 那个模板抄，约 300 行 + `test/m13.test.js`）
   - `POST {baseUrl}/models/{model}:generateContent`（非流式）／`:streamGenerateContent?alt=sse`（流式）
   - 鉴权 `x-goog-api-key`（Vertex 那套是 OAuth `Authorization: Bearer`、模型名写成 `publishers/google/models/...`，算另一条线）
   - 请求：`contents[].parts[]`（role 是 `user`/`model`，**必须交替**）、`systemInstruction`；参数全塞进
     `generationConfig`（`maxOutputTokens`/`temperature`/`topP`/`stopSequences`/`responseMimeType`/`responseSchema`）；
     工具是 `tools[].functionDeclarations` + `toolConfig.functionCallingConfig.mode`
   - 响应：`candidates[].content.parts[]` + `finishReason`（`STOP`/`MAX_TOKENS`/`SAFETY`/`RECITATION`/`PROHIBITED_CONTENT`
     要映成 `stop`/`length`/`content_filter`）；用量是 `usageMetadata`
   - 流式：真 SSE 但**没有事件名、也没有 `[DONE]`**，靠 `finishReason` 收尾
   - 模型名在**路径**里（和 `cloudflare-workers-ai` 一样），所以 `realModelId` 不进请求体
   - ⚠ 思考：多轮工具调用里 `parts[].thoughtSignature` 必须原样回传，丢了会被 400 / 降级；
     思考预算走 `generationConfig.thinkingConfig.thinkingBudget`，和我们现在的 `reasoning_effort` 对不上。
     建议照现有惯例：**明确不做思考**，在 README 已知限制里写一条（跟 Anthropic 面那条一个写法）。
   - 图片只有 `inlineData`（base64），没有"图片 URL"这回事 —— 要么自己下回来转 base64，要么明确拒
2. **下游方言 `gemini`**（贵得多：等于第四种客户端协议 + 一套 `faces/` 实现 + 流式事件 + 后台地址栏）
