# LLM API 聚合网关（服务端版）· 详细设计文档

- 版本: **v0.4**（自用优先：极简鉴权、不做 HTTPS、前端零框架、凭据加密）
- 日期: 2026-09-10
- 状态: 设计草案（待评审）
- 定位: **单实例、自用**的服务：服务端持有各家上游 key；客户端输入一道"访问口令"即可连接（等同门禁，不做账号体系）

**v0.2 → v0.4 关键变更**

1. **部署形态**：不做 Windows 桌面程序（.NET/WPF 方案作废）。改为**跑在 Linux 服务器上的常驻服务**，本机不占内存、不用开机自启。
2. **界面**：桌面 UI → **网页管理后台**（提供商/模型配置、拖拽排序、客户端 Key、日志、统计）。
3. **对外 API 极简**：**只做 `/v1/chat/completions`（含流式）与 `/v1/models`**。其余常用端点（usage/billing/credits）返回**合理的假数据**避免客户端报错，未列出的 `/v1/*` 返回标准 404。
4. **公网可用**：服务端持有上游 key；客户端调用时填一道**访问口令**（详见 §3.2，后续版本进一步简化为门禁级）。
5. **上游拒绝策略由用户选**（每个来源可独立设置）：`不停用` / `倒计时检测`（默认 5 分钟，可自定义）/ `停用不检测`。
6. **不向客户端报错**：上游任何失败都**静默换源**，只有全部候选都不可用时才返回一条统一错误（不含上游任何细节）。
7. **配置拆两层**：**提供商配置**（地址、apiKey、速率等） + **模型配置**（model id）。
8. **速率可填 0**：表示"不做本地速率限制，直接试能不能用"（配合倒计时检测最实用）。
9. **排序不进表单**：单独的**拖拽排序页**。
10. **响应头解析先不做**（L1 层暂缺，后续可加）。

**v0.3 → v0.4 关键变更（自用优先的简化）**

11. **鉴权极简化**：客户端 key = 一道**访问口令**（可多条、可随时更换），**不做限流、配额、账号体系、按口令统计**。理由（用户）：自用工具，口令只相当于门禁，没人会把地址和 key 公布出去。
12. **不做 HTTPS**：自签名证书客户端报错、在线证书麻烦；默认 HTTP 供内网/自有服务器使用。要公网访问请自行套 **Cloudflare Tunnel** 或 TLS 反代。
13. **前端零框架**：原生 **HTML + CSS + JavaScript**（不用 Vue），拖拽排序用原生 Drag & Drop。
14. **凭据加密（用现成库）**：上游 apiKey、下游访问口令、管理口令全部用 **`libsodium-wrappers`**（secretbox 认证加密）入库（管理口令 2026-09-15 起，以前是 argon2 哈希，见 §9）；主密钥来自环境变量 `APP_SECRET`。存储用 **`better-sqlite3` + `Knex`**（迁移交给 Knex），**不自研加密与存储**。
15. **提示改为字段级内联**：只针对免费来源——「速率填 0」的提示贴在速率框旁，「策略选不停用」的提示贴在策略下拉旁；**不做汇总、不做组合/并排提示**（用户指出那纯属重复）。
16. **付费来源不做本地限制**：平台不会限制你（巴不得你多用），速率/额度字段对付费来源**默认留空**，想自保可以填；也不弹提示。
17. **探测不是独立开关**：由拒绝策略三选一决定（只有『倒计时检测』会探测）——用户指出这点属于画蛇添足。
18. **部署目标**：**Debian 12 + Docker Compose**（`restart: unless-stopped`，不需要 systemd）；**默认双栈监听**（`::`，IPv4 与 IPv6 同一端口；没 IPv6 的机器自动退回 `0.0.0.0`），不做"是否允许外部访问"的后台开关 —— 换成管理端来源闸（§9）。
19. **技术栈定案**：Node.js + **纯 JavaScript**（不用 TS）+ **Express** + **better-sqlite3 + Knex** + **libsodium-wrappers**（加密，口令也是它）+ 原生 HTML/CSS/JS 后台。

## 0. 项目基准（用户硬性要求，后续一切决策以此为准）

1. **一个 API 调用所有 API**：本服务暴露 OpenAI 兼容入口，内部路由到多家上游。
2. **服务端持有上游凭据**：提供方完全通用（地址 + apiKey + 速率），无预设白名单；客户端只用本服务的 key。
3. **速率填写框是核心差异化**：每个提供方由用户直接填它的速率（如 `40 请求/分钟`）。网关据此判断该源**此刻能不能用**；填 `0` 表示不做本地限制、直接试。
4. **不排队、不等待**：某源此刻不可用 → **直接换下一个源**；换不了就返回统一错误。
5. **不向客户端暴露上游错误**：失败静默换源，错误详情只进后台日志。
6. **选源顺序 = 先看"能不能用"，再按用户在拖拽页里排的顺序**。
7. **付费来源兜底**：仅当**免费来源全部不可用（报错停用或此刻都不空闲）**时才使用付费来源。
8. **上游拒绝处理三选一**（每个来源）：不停用 / 倒计时检测（默认 5 分钟）/ 停用不检测。
9. **界面**：网页管理后台，**前端零框架**（原生 HTML/CSS/JS），Linux 服务器优先 Docker 部署。
10. **鉴权 = 访问口令**：客户端填一道口令即可用（等同"电脑密码"，仅限自己连接）。**不做**限流、账号体系、口令生命周期管理、按口令的用量统计。
11. **不做 HTTPS**：默认 HTTP，面向内网/自有服务器；需要公网访问请自行套 Cloudflare Tunnel 或 TLS 反代。**切勿把明文端口直接暴露到公网。**
12. **凭据加密**：上游 apiKey 与客户端访问口令都必须加密/哈希存储（主密钥来自环境变量或本地密钥文件，不落库）。
13. 明确不做：额度刷满/批量任务器（用户判定无意义）、排队等待、图像/视频/嵌入、多租户计费系统。

## 1. 目标、非目标与成功判据

### 1.1 目标

在用户自己的 Linux 服务器上跑一个常驻服务：

- **对外（客户端面）**：`POST /v1/chat/completions`（含 SSE 流式）、`GET /v1/models`。任何 OpenAI 兼容客户端填 `base_url` + 本服务的 key 即可用。
- **对内（上游面）**：把请求按"可用性 + 用户排序"路由到某一上游；上游被限流/报错时静默换下一个；按所选策略决定该源何时恢复。
- **管理面**：网页后台完成全部管理（提供商/模型/Key/排序/日志/统计），不需要 SSH 改文件。

### 1.2 非目标（明确不做）

- 不做多租户/充值/计费面板；**客户端访问口令只做门禁**，不做限流、配额、账号体系（自用无意义）。
- 不做 Windows/macOS 桌面客户端（本机只当普通 API 客户端用）。
- **不在应用内做 HTTPS/TLS**（自签名客户端报错、在线证书麻烦）：默认 HTTP，公网访问由部署方自行套 Cloudflare Tunnel 或反代。
- 不做额度刷满、批量任务器、排队等待（用户已裁定）。
- 不做图像/视频/嵌入/语音等其它模态（只做 chat + models）。
- 不做响应头解析（限流头先不读，后续可加）。
- 不内置任何"共享 key / 免费源倒卖"资源。

### 1.3 成功判据（DoD）

1. 客户端只填一个本服务的 key，就能连续用上多个免费上游，且客户端全程看不到上游是谁、也看不到上游报错。
2. **限 6 请求/分钟的源 + 一个备用源，连发 20 次：该源按速率吃掉它该吃的部分，其余自动走备用源；全程零客户端可见错误、零人工干预。**（核心验收项）
3. 某源被限流后按所选策略处理：`不停用` → 下次照旧尝试；`倒计时检测` → 5 分钟后自动探测，恢复即重新可用，未恢复继续倒计时（额度刷新后自动复活）；`停用不检测` → 一直停到后台手动启用。
4. 免费来源全不可用 → 自动走付费来源（若已配置）；付费也全不可用 → 返回统一错误（无上游细节）+ 建议重试时间。
5. 在后台拖拽调整来源顺序后，下一次请求的选源结果立即改变。
6. 后台能看清：每个来源此刻能否使用、原因、恢复倒计时、被探测次数；以及最近每次请求的换源链路。

## 2. 总体架构

### 2.1 技术栈（推荐）

**Node.js 20 + 纯 JavaScript + Express + SQLite（WAL）+ 原生 HTML/CSS/JS 后台 + Docker（Compose）**

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js 20 LTS + TypeScript | 单进程异步 IO 天然适合做转发网关；SSE 透传直接、无额外依赖 |
| Web 框架 | **Express** | 资料/示例最多，SSE 直接 `res.write()`，静态托管一行 `express.static`；对本项目（单实例自用）性能差异无意义 |
| 存储 | SQLite（better-sqlite3，WAL 模式） | 单实例自用完全够；单文件、易备份（拷 db 文件即可）；**敏感字段加密后入库**（§8.1）|
| 后台前端 | **原生 HTML + CSS + JavaScript（零框架）** | 用户熟悉手写页面、不用 Vue；拖拽排序用原生 Drag & Drop（`draggable` + `dragover`/`drop`），不引第三方库 |
| 部署 | Docker + docker-compose（**host 网络模式**） | 一键起、升级简单；**默认 HTTP**（内网/自有服务器）；公网需自行套 Cloudflare Tunnel 或反代 TLS |
| 定时任务 | 进程内定时器（探测/重置扫描） | 单实例，无需分布式锁 |

备选：Python FastAPI（开发更快，异步 SSE 可行）、Go（内存最小、单二进制，但后台前端工作量一样）。
**已定**：后端 **纯 JavaScript**（不写 TS，不引构建步骤）；框架 **Express**（理由见 §13）；存储 **better-sqlite3 + Knex**；加密 **libsodium-wrappers**（上游 key / 下游口令 / 管理口令都是它）。备选（不采用）：Fastify（性能优势在此无意义）、Python FastAPI、Go（开发效率优先于内存占用）。

### 2.2 组件结构

```
Linux 服务器（单进程 Node 服务，Docker 内）
├─ 对外 HTTP（Express）
│   ├─ POST /v1/chat/completions   ← 主入口（含 SSE 流式）
│   ├─ GET  /v1/models             ← 合并输出所有启用模型
│   ├─ 假数据端点：/v1/usage · /v1/billing/subscription · /v1/credits（返回零值占位）
│   └─ 其它 /v1/* → 404（OpenAI 格式错误体）
├─ 客户端鉴权（访问口令列表：启停 / 一键更换 / 可选 IP 白名单；不做限流与统计）
├─ 模型目录（提供商 × 模型 两层配置合并，去重）
├─ 路由引擎（可用性过滤 → 拖拽排序 → 免费组优先 → 付费组兜底）
├─ Provider 适配器层（按来源的 `adapter` 字段分发）
│   ├─ openai-compatible（覆盖绝大多数：NVIDIA NIM / Mistral / ModelScope / 各家中转）
│   ├─ anthropic（Anthropic Messages API：请求按 Messages 形状发，响应/流式翻回 OpenAI 形状）
│   └─ cloudflare-workers-ai（模型在 URL 路径里，`{result:{response}}` 同样翻回 OpenAI 形状）
│      · 白名单来自适配器注册表：下拉框里有的，代码里就一定有实现
├─ 速率准入（手填速率 → 漏桶 nextSlotAt；填 0 则不做限制）
├─ 失败策略与状态机（不停用 / 倒计时检测 / 停用不检测；认证类单独处理）
├─ 探测任务（冷却到期后自动发极小请求，验证是否恢复）
├─ 用量与日志（调用记录 + 按来源/按天统计；不按口令拆分）
└─ 管理 API + 静态后台页面（登录后使用）
   SQLite（providers / provider_models / rate_state / source_state / access_keys / call_log / settings）
```

### 2.3 一次请求的处理流程

1. 客户端 `POST /v1/chat/completions`（`Authorization: Bearer <本服务key>`，可选 `stream: true`）。
2. 校验访问口令（不对 → 401）；口令只做门禁，不做限流。
3. 解析请求里的 model（见 §3.5 的四类名字）得到"这次要用哪些 (来源, 模型)"。
4. 路由：过滤掉**此刻不可用**的来源 → 剩下的按**用户排的顺序**试（`All` 用「All模型顺序」页的顺序、模型组用组内顺序）；`All` 是免费组优先、付费组兜底，模型组则完全按你排的来（可以混免费付费）。
5. 对首选源做准入检查（速率是否空闲）→ 通过则转发；不通过 → 视为不可用，取下一个。
6. 上游失败（任意 4xx/5xx/429/超时/连接失败）→ **记录 + 按该源策略处理 + 静默换下一个**（首字节前可换；首字节已发出则终止本次响应，让客户端自行重试）。
7. 成功 → 流式/整包回传；记录 tokens、耗时、命中的来源、是否 fallback。
8. 所有候选都不可用 → 返回**统一错误**（见 §3.4），建议重试时间取"最早恢复时刻"。

### 2.4 后台定时任务

- **探测循环**：对处于"倒计时检测"冷却中的来源，到期后发一次极小探测请求（§6.3）；成功→恢复可用，失败→重新开始倒计时。
- **周期重置扫描**：日额度/每日限流的来源在跨天后自动恢复可用。
- **统计汇总**：定期把调用日志汇总成按天数据，避免后台查询变慢。

## 3. 对外 API（客户端面）

### 3.1 端点清单

| 端点 | 说明 |
|---|---|
| `POST /v1/chat/completions` | **主入口**。支持流式（`stream:true` → SSE）；请求/响应字段与 OpenAI 保持一致，尽量原样透传 |
| `GET /v1/models` | 发布四类模型名：虚拟模型 `All` + 模型组 `ModelGroup/<组名>` + **带类别前缀的具体模型名**（见 §3.5）。`owned_by` 写本服务（虚拟名字）或 `Free/<来源id>`、`Pay/<来源id>`，**不暴露上游地址** |
| `GET /v1/models/<id>` | 单个查询（`id` 里可以带斜杠，如 `Pay/paid-b/m-x`）|
| `GET /v1/usage`、`/v1/billing/subscription`、`/v1/credits` | **假数据占位**（零用量、零额度），避免客户端探测时报错 |
| 其它 `/v1/*` | 404，OpenAI 格式错误体 |

> 设计取舍：端点越少越不容易出问题；假数据是为了兼容那些"启动时探测用量"的客户端。

### 3.2 客户端鉴权（访问口令，极简）

- 服务端维护访问口令。**界面上就只有一条**（用户 2026-09-11 的裁定）：后台「密码」页一个框管一条 —— 显示 `sk-****` 掩码、可一键复制、可「更改 apikey」（换掉旧的、建新的）。后端表仍支持多条，只是界面不再暴露。**没有配额、没有过期时间、不按口令统计用量**；只有一个**失败锁定**（同来源连续失败 5 次锁 5 分钟，见 §9）。
- 客户端 `Authorization: Bearer <口令>`；口令不对 → 401（必须告诉客户端，否则没法用）。
- **存储（用户裁定 2026-09-12，取代 09-11 的方案）**：**只留能还原的那一份** —— `key_enc`（libsodium secretbox 密文）。
  - 为什么删掉 argon2 哈希：从 007 起就已经存了一份能解出来的密文，后台靠它显示掩码/复制。既然密文在库里，哈希**不再提供任何额外保护** —— 拿到整库的人要么也有 `APP_SECRET`（那密文就是明文），要么没有（那哈希也只能硬碰运气，而这口令是 32 字节随机的，本来就猜不着）。留着只是"两套真相"：改口令要写两份、判断"能不能显示"要看另一列、老数据还会出现"哈希能校验但密文没有"的怪状态。
  - 校验方式随之改成**解密 + 常量时间比对**（`nodeCrypto.timingSafeEqual`）；顺带把每次 `/v1/*` 鉴权从"逐条 argon2（几十毫秒）"变成"逐条解密（微秒级）"。
  - 代价如实写：**库 + `APP_SECRET` 一起泄露 = 下游口令直接暴露**，与"明文放 `.env`"同一风险等级，但更可控（密钥可单独注入、`.env` 可以没有）。**管理密码 2026-09-15 起也走同一套**（以前是 argon2 哈希，见 §9）。
  - 老数据（没有密文的行）现在既显示不出也**校验不过**，等于失效；启动时会 warn 一条「有 N 条下游口令无法还原」，后台「密码」页提示点「更改 apikey」换新的。`backfillEncrypted`（靠哈希校验把 `.env` 明文补成密文的那条升级路径）随之删除。
  - 迁移 `20260915_0010_access_key_no_hash.js` 负责删列。
- 可选 **IP 白名单**（设计里有、**尚未实现**；内网固定 IP 场景很省心）。
- "允许无口令访问"开关：默认关闭；仅当服务只在 `127.0.0.1` 或反代已鉴权时可临时打开。
- **设计理由（用户裁定）**：这是自用工具，口令的作用是"别让扫端口的人白嫖"，不是对外提供服务，因此不做账号体系与限流。

### 3.3 流式契约

- 上游支持流式则直接透传 SSE；不支持流式时由本服务缓冲并转成 SSE 输出。
- 首字节前失败：静默换源，客户端无感。
- 首字节后断流：**不换源、不重放**（内容已部分发出，无法回滚），立即结束本次响应并记账；客户端按 SSE 中断自行重试。
- 透传上游返回的 `usage`（若有）用于本地统计。

### 3.4 错误契约（重点："不报错"的边界）

| 情况 | 对客户端 | 说明 |
|---|---|---|
| 虚拟名字（`All`、模型组）：上游任意失败（429/5xx/超时/连接失败） | **不返回**，静默换源 | 上游细节只进后台日志 |
| 虚拟名字（`All`、模型组）：全部候选不可用/全失败 | `503` + 统一文案（如「服务暂时不可用，请稍后重试」）+ `Retry-After` | **不含**上游名称、模型、错误码、额度信息 |
| 指定来源：本机速率没到点 | `429` + `Retry-After`（说清是本地限速） | 不换源：你要的就是这个来源 |
| 指定来源：上游报错 | **原样转发**（状态码、响应体、`Retry-After` 都照搬） | 用户明确要的来源，出了问题必须让他看见 |
| 指定来源：连不上上游（超时/DNS） | `502` | 没有上游响应可转发，给个明确错误 |
| 指定来源：此刻不可用（冷却中/已停用/额度用满） | `503`（`source_unavailable` + 原因）+ `Retry-After` | 不偷偷换源 |
| 模型名写错：裸名字 / 漏了 `Free/`-`Pay/` 前缀 / 来源不存在 / 前缀与来源的免费付费属性不符 / 该来源下没这个模型 / 模型组不存在 | `404`（`model_not_found`） | 错误文案里给出正确格式（漏前缀时直接给出"写成 `Free/xxx/yyy`"） |
| 用了已经废弃的名字 `auto` | `404` + 「`auto` 已改名为 `All`」 | 明确告诉怎么改，不说一句含糊的"模型不存在" |
| 客户端请求本身非法（请求体错误） | `400`（OpenAI 格式） | 换源解决不了这类问题，必须告诉客户端 |
| 访问口令无效 | `401` | 与上游无关；口令不设限流，故不存在"口令超限"这类 429 |

### 3.5 模型名规则（四类名字）

下游请求体里的 `model` **必须**是下面四种之一（`GET /v1/models` 返回的就是这些名字）：

| 名字 | 含义 | 行为 |
|---|---|---|
| `All` | 虚拟模型：交给本服务自己挑 | 按「All模型顺序」页的顺序（**免费组在前 → 付费兜底组**，组内按模型条目的拖拽顺序）逐个试；某个来源失败就换下一个；全都不行 → `503` |
| `Free/来源id/上游模型名` | 指定某个**免费**来源的模型 | **不换源**：本机限速报 `429`，上游报错原样转发 |
| `Pay/来源id/上游模型名` | 指定某个**付费**来源的模型 | 同上 |
| `ModelGroup/组名` | 你自己排的一组模型（见 §3.6） | 按**组内顺序**逐个试，失败往下换；全都不行 → `503`。组里**可以混免费和付费**，完全按你排的来 |

**虚拟名字（`All` 和每个模型组）会额外发布上下文长度**（`context_length` + `context_window`，全局设置 `auto_context_tokens`，默认 `256000`，填 `0` = 不发布）：

- 起因：客户端（如 DSH）不知道窗口时只能用**自己的默认值**去攒上下文（DSH 默认 256k），撞上窗口更小的来源就报"上下文超长"；而这类错误**只能靠错误文案的正则去识别**，识别不了就是硬失败。
- 所以由我们提供权威值，让客户端**提前压缩**。虚拟名字可能落到任何一个来源，因此这个值必须按**最窄的那个**给（填大了会出现"攒到超长才压缩 → 撞小窗口"）。
- **不做**：模型级窗口发布（要给每个模型填一遍，暂时不值当）；窗口**动态取最小值**（要客户端预算稳定，不能我们自己变来变去）。
- 客户端怎么读：DSH/OpenRouter 系会在拉 `/v1/models` 时读 `context_window` 或 `context_length`（两个都发了）；读不到的客户端退回自己的默认值，行为与之前一致（所以这个改动对它们零影响）。

细则：

- **名字里没有"显示名/别名"这种东西了**（用户裁定 2026-09-11：一套名字一个含义）。模型的「对外显示名」（`display_name`）和「别名」（`aliases`）连同数据库里那两列一起删掉（migration `20260913_0008_model_groups.js`），请求只按 `model_id` 精确匹配。
- 前缀**大小写不敏感**（`pay/`、`PAY/`、`MODELGROUP/` 都认），但对外一律发布规范写法。这样升级那一刻，老客户端里写着的 `PAY/xxx/yyy` 不会当场断掉。
- 上游模型名自身可以带斜杠（如 `deepseek-ai/DeepSeek-V4-Flash`），所以 `来源id/` 之后按**第一个斜杠**切完，剩下的**整体**就是模型名：来源 `modelscope-cn` 下的它，对外名字是 `Free/modelscope-cn/deepseek-ai/DeepSeek-V4-Flash`。
- 不带类别前缀的裸名字（`gpt-4o-mini`，或老写法 `modelscope-cn/xxx`）、来源 id 写错、免费来源加了 `Pay/`、付费来源写成 `Free/`、模型名不存在、模型组不存在 —— 一律 `404`，并在文案里提示正确格式：漏前缀时会直接给出"写成 `Free/来源id/模型名`"这种准确答案；**不做**"名字猜来源"的模糊匹配（猜错了会静默打到别的来源，比报错更糟）。
- 已经废弃的 `auto` → `404` + 「`auto` 已改名为 `All`，请把模型名改成 `All`」。
- 虚拟名字的失败不暴露内部细节：客户端只需要知道"现在不行，过 N 秒再试"。
- **设计理由（用户裁定）**：指定来源时用户要的是确定性（"我就要用这家"），所以既不换源也不吞错误；`All` / 模型组要的是"永远有得用"，所以吞掉细节静默换源。

### 3.6 模型组（`ModelGroup/<组名>`）

"一个 api 调用所有 api"落到了两处：`All` 是**全局一套顺序**，模型组是**你自己编的若干套顺序**。

- 数据：`model_groups`（`id` / `name`（唯一）/ `sort_order`）+ `model_group_items`（`group_id` / `provider_model_id` / `sort_order`，两条外键都是 `ON DELETE CASCADE`）。一个模型可以同时出现在多个组里。
- **组内顺序 = 选源优先级**，和「All模型顺序」页一样支持拖拽排序。
- **允许混免费与付费**：组里怎么排就怎么试，不吃"免费组在前"那套规则（`All` 才吃）。
- 组名就是个普通字符串：后台是个没有"保存"按钮的输入框，失焦即存、改名即时生效（旧名字立刻 404）。
  - 限制：不能为空、最多 64 字符、**不能带斜杠或空格**（否则 `ModelGroup/a/b` 没法解析）、不能重名。
- 组不存在 → `404`（文案「没有名叫「x」的模型组」）；组在但里面没有可用模型（空的 / 模型全被禁用 / 全在冷却）→ `503`，与"全部来源都不可用"同一个口径。
- 删组不影响模型本身；**删模型会自动清掉它在各个组里的条目**（`pruneForProviderModel`），不留指向空气的脏行（删提供商则是外键级联一路删下去）。
- 界面上：最上面固定一行「＋ 添加模型组」（组多了也不会被挤下去），下面每组一行 `[组名输入框][展开箭头]`，点开才显示组内配置（加模型的下拉框 + 每行的删除按钮）。

### 3.7 图片（视觉）支持

用户 2026-09-12 的原话：

> "加一下图片支持怎么样。（All或者ModelGroup）给下游的信息就是支持接受图片。然后看列表里哪个支持图片理解。没有就报错。因为给下游发能不能接受图片都不能动态调整，下游只会获取一次这个模型能不能发图片。所以只能接受，收到了再看上游行不行。"

这条把设计钉死了，分成两半：

**① 对外（`/v1/models`）**

| 名字 | 怎么声明 | 为什么 |
|---|---|---|
| `All` / `ModelGroup/<组名>` | **永远**声明能收图 —— `architecture.input_modalities: ["text","image"]`、`architecture.modality: "text+image->text"`，顶层再发一份 `input_modalities` | 下游只在拉列表时看一眼能力、之后不会动态调整，所以**只能先答应下来**；真有没有能看图的，收到请求再说 |
| `Free/…` / `Pay/…` | 按模型上的 `supports_vision` 标记声明（`text->text` 或 `text+image->text`） | 具体模型的能力是确定的，如实说 |

发这几种写法是因为各家客户端读的不一样：`architecture.*` 是 OpenRouter 那套（[OpenRouter provider 文档](https://openrouter.ai/docs/guides/community/for-providers)），顶层 `input_modalities` 也有客户端读。

**② 对内（真收到带图的请求）**

1. 从 `messages[].content` 里认出图片：`image_url`（标准）以及 `image` / `input_image` 两个别名。
2. 候选只保留 `supports_vision` 为真的模型：
   - **一个都没有** → `400 image_not_supported`（配置问题，等也不会好），文案里说清怎么修：去「提供商」页那个模型的「图片」按钮上点一下。
   - **有，但此刻都不可用** → `503 no_available_source`（普通的"暂时不行"）。两者语义完全不同，不能混。
   - 指定来源（pinned）时同理：那个模型没标图片 → `400`，**不换源也不打上游**。
3. **绝不把图片丢掉再发出去**（不降级成纯文字）—— 那样客户端会收到一个"没看图"的回答，比报错糟得多。

适配器层面：`openai-compatible` 原样透传（图片本来就在 body 的 content parts 里）；`anthropic` 把 `image_url` 翻成 Anthropic 的 `image` 块（`data:` URL → `{type:'base64', media_type, data}`，http 图片 → `{type:'url', url}`，见 `adapters/anthropic.js` 的 `toBlocks`）；`cloudflare-workers-ai` 的 `messages` 本来就在参数白名单里，直接透传。

数据：`provider_models.supports_vision`（migration `20260914_0009`，**默认 0** —— 老数据升级上来不会凭空多出"能看图"的假能力）。后台「提供商 → 模型列表」每行有个「图片」按钮切换它，模型名旁边挂一个 `图片` 小标（「All模型顺序」和「模型组」页也看得到）。测试 `test/m9.test.js`（6 个用例）。

## 4. 配置模型（提供商 + 模型 两层）

### 4.1 提供商配置（Provider）

| 字段 | 说明 |
|---|---|
| `id` / `name` | 唯一标识 / 显示名 |
| `enabled` | 是否启用 |
| `isPaid` | 免费/付费标签（决定它属于免费组还是付费兜底组）|
| `adapter` | 上游协议：`openai-compatible` / `anthropic` / `cloudflare-workers-ai`（**白名单来自适配器注册表**，选中就一定有实现，不会拿错协议去打上游）|
| `baseUrl` | 上游地址（anthropic 填 `https://api.anthropic.com/v1`，兼容填域名也行；cloudflare 固定 `https://api.cloudflare.com/client/v4`）|
| `apiKey` | 上游密钥（服务端保存；建议加密存储 + 界面打码）|
| `accountId` | **Cloudflare Workers AI 用**（账号 ID，模型地址 `/accounts/{id}/ai/run/{model}` 里的那一段）；其它协议留空 |
| `proxyUrl` | 可选出网代理（境外源直连失败时用）|
| `rateLimits` | **速率填写框**：`{kind, value}`，kind ∈ `rpm`/`rpd`/`tpm`/`tpd`/`concurrency`；**`value = 0` 表示不做本地限制**；**付费来源可不填**（平台通常不限你，本地限制只是自保）|
| `quota` | 可选额度：`{kind: requests/tokens/credits/neurons, total, period: day/month/none, used}`；付费来源可不填 |
| `rejectPolicy` | **上游拒绝时的策略（三选一；探测与否由它决定，没有独立开关）**：`keep_trying`（不停用、不探测）／ `cooldown_probe`（倒计时检测：按等待时长表探测）／ `stop_manual`（停用不检测、人工恢复）|
| `cooldownSeconds` | ~~已废弃~~（用户裁定 2026-09-11）：等待时长从"每个来源配一个秒数"改成**全局的等待时长表（退避）**，见 §6.3。字段还在库里但不再使用 |
| `probeModel` | ~~已移除~~（用户裁定：没用）。恢复探测改为**自动优先探"刚失败的那个上游模型"**，见 §6.3 |

**两条提示：贴在触发它的字段旁边（字段级内联，仅免费来源）**

| 触发条件 | 提示位置与内容 |
|---|---|
| **免费**来源的「速率」框填 `0` | 提示就贴在**速率框**旁：⚠️「该源不做本地限速：永远算空闲、会被优先反复选用，容易撞限流。」 |
| **免费**来源的「策略」下拉选 **不停用** | 提示就贴在**策略下拉框**旁：⚠️「该源失败后既不冷却也不停用，下次请求还会选到它：反复撞错、白白浪费机会，可能触发平台风控。」 |
| 付费来源 | 不提示（平台不会限制你，账单是你自己的选择）|

- **不做任何汇总、"组合提示"、并排展示**（用户裁定）：每个提示只跟着自己的字段出现。你在速率框已经看过限速提示，选策略时不该再被重复一遍。

### 4.2 模型配置（Model）

每个提供商下挂若干模型，模型配置很轻：

| 字段 | 说明 |
|---|---|
| `providerId` | 所属提供商 |
| `modelId` | 上游真实模型 id（如 `Qwen/Qwen2.5-72B-Instruct`、`@cf/meta/llama-4-scout-17b-16e-instruct`）|
| `enabled` | 是否对外提供 |
| `rateLimitOverride` | 可选：**模型级速率覆盖**（有些平台限速是按模型算的）|
| `contextTokens` / `notes` | 可选元信息 |

> 用户裁定 2026-09-11：模型的「对外显示名」(`display_name`) 和「别名」(`aliases`) **已删掉**（连同库里那两列）——"一套名字一个含义"，模型对外就是 `Free|Pay/<来源id>/<上游模型名>`，日志、`/v1/models`、报错文案全用这一套。

> `/v1/models` 的输出 = 所有启用模型的并集（同一 id 被多家提供时去重，选源逻辑自动在多家之间做可用性+排序选择）+ 虚拟名字（`All` 和每个模型组）。

### 4.3 排序（单独的拖拽页）

- 「**All模型顺序**」页：分两组 —— **免费组**、**付费组**；组内拖拽调整顺序，**组间不可交叉**（代码保证付费只在免费全不可用时才被使用）。这里的顺序就是 `All` 的尝试顺序。
- 「**模型组**」页：每组一个独立的顺序，组内也支持拖拽；模型组**不受"免费在前"约束**，完全按你排的来（见 §3.6）。
- 顺序即优先级：可用性相同的情况下，排在前面的先被选中。
- 排序页每行直接显示：启用状态、当前可用性（可用 / 冷却中 + 倒计时 / 停用）、手填速率、今日调用量。拖拽后立即生效（无需重启）。

### 4.4 上游协议适配器（3 种）

适配器只做一件事：**把"OpenAI 形状"与上游协议的形状互相翻译**。路由、限速、状态机、日志全部协议无关。

| 适配器 | 端点 | 鉴权 | 关键差异 |
|---|---|---|---|
| `openai-compatible` | `{baseUrl}/chat/completions` | `Authorization: Bearer` | 无（原样透传，只改模型名）|
| `anthropic` | `{baseUrl}/v1/messages`（baseUrl 已带 `/v1` 就不重复加） | `x-api-key` + `anthropic-version: 2023-06-01`（同时带 Bearer 兼容中转） | `system` 单独成字段；messages 只能 user/assistant 且**必须交替**（相邻同角色自动合并）；`max_tokens` **必填**（客户端没传补 4096）；响应/流式都是命名事件 |
| `cloudflare-workers-ai` | `{baseUrl}/accounts/{accountId}/ai/run/{model}` | `Authorization: Bearer` | **模型名在路径里**，请求体不带 `model`；参数走白名单；响应是 `{result:{response,usage}}`；错误可能是 HTTP 200 + `success:false` |

每个适配器要实现 4 件事（见 `src/gateway/adapters/`）：

```
buildChatRequest(provider, model, clientBody, {stream}) → { url, headers, payload }
buildProbeRequest(provider, model)                      → { url, headers, payload }   # 探测/测试共用一个最小请求
normalizeResponse(json, ctx)                            → OpenAI 形状；认不出来返回 null（当作上游故障，换源）
normalizeStreamData(data, ctx)                          → { chunks:[...] } / { passthrough } / { error } / null
```

- 翻译型适配器声明 `translates = true`：**上游的 `event:` 之类行会被丢掉**，客户端只看到我们生成的 `data:` 行（否则 Anthropic 的事件名会漏给客户端）。
- 流式用量：Anthropic 的 `message_start.input_tokens` 与 `message_delta.output_tokens` 会合并，并在 `[DONE]` 前补一个"只有 usage、没有 choices"的 chunk（等价 OpenAI 的 `include_usage`）；有的协议不发 `[DONE]`，流结束时也会补上。
- **工具调用（function calling）也是翻译的一部分**（2026-09-11 补齐，见下表）。客户端那侧只写 OpenAI 那一套。

| 环节 | OpenAI | Anthropic |
|---|---|---|
| 工具定义 | `{type:'function',function:{name,description,parameters}}` | `{name,description,input_schema}`（去掉包装、`parameters`→`input_schema`） |
| 模型要调工具 | `message.tool_calls[]` + `finish_reason:'tool_calls'` | `content:[{type:'tool_use',id,name,input}]` + `stop_reason:'tool_use'` |
| 工具结果回灌 | `{role:'tool', tool_call_id, content}` 单独消息 | 并进 **user** 消息的 `{type:'tool_result',tool_use_id,content}` 块 |
| 参数格式 | `arguments` JSON 字符串（流式是碎片） | `input` 对象 |
| 并行调用 | `delta.tool_calls[].index` 碎片交错 | `content_block_start` + `input_json_delta` 块事件流（用 ctx 记住块 index → 工具序号） |
| 选择策略 | `tool_choice: 'auto'/'required'/'none'/{函数}` | `{type:'auto'/'any'/'none'/'tool',name}`；`parallel_tool_calls:false` → `disable_parallel_tool_use` |

- 多轮工具循环要求**消息序列重排**：OpenAI 的 `[assistant(tool_calls), tool, tool]` → Anthropic 的 `[assistant([tool_use,tool_use]), user([tool_result,tool_result])]`，并且只把工具结果并进"纯工具结果的 user 消息"，不会混进用户正常提问。
- **已知边界（明确不做，用户裁定 2026-09-11）**：Anthropic 开启扩展思考时要求把上一轮的 thinking 块（带 `signature`）原样回放，否则 400；我们不保存上游的非标准块，所以"上游强制 thinking **且**严格校验签名"这个组合下，多轮工具循环会被上游拒绝。
  - **不做的理由**：用 Anthropic 协议的上游本就少 → "强制开思考"的更少 → 再叠加"严格校验签名"就极少了；而且失败形态是**上游明确的 400**（日志可见），不是静默出错。
  - 实测：DeepSeek 的 Anthropic 端点带 `signature` 但**不要求回放**（多轮工具循环正常）；Claude 官方不开 thinking 时不会返回思考块，也碰不到。
  - 真遇到时的补法（留档）：按 `tool_use.id` 缓存 thinking 块（带上限的 LRU），下一轮按 id 回放；这个规则可以用严格假上游测出来。
- 客户端发来的 `thinking` / `reasoning_effort` 等参数**不转发**给 Anthropic。
- 新增协议 = 在 `src/gateway/adapters/` 加一个实现并注册进 `index.js`；白名单与后台下拉框都从注册表取，不会出现"选项里有、代码里没有"。

## 5. 速率、准入与用量

### 5.1 信息源与现状

| 级别 | 说明 | 本版状态 |
|---|---|---|
| **L0** | **用户手填速率**（速率填写框）| **生效，第一权威** |
| L1 | 上游限流响应头（`x-ratelimit-*` 等）| **先不做**（后续可加，加的时候只用于校准，不覆盖 L0）|
| L2 | 上游错误语义（429 / 额度 / 认证 / 5xx）| 生效（触发失败策略）|
| L3 | 官方用量查询接口 | 暂不做 |
| L4 | 本地计量（调用次数、tokens、可选额度扣减）| 生效（用于准入判定与后台统计）|

### 5.2 速率填 0 的语义

- `0` = **不做本地速率限制**：该源永远视为"此刻空闲"，可被无限次选用。
- 适用场景：平台的限速是动态的、或按"每日次数 + 动态速率"（例如 ModelScope 这类）——只能"试试能不能用"。
- **代价**：撞 429 的概率显著升高。建议该源搭配 `cooldown_probe`（撞一次就冷却 5 分钟再试），而不是 `keep_trying`。
- **提示规则**（§4.1）：**只对免费来源**，且提示贴在**触发它的那个字段旁**——"填 0"贴在速率框旁，"策略 = 不停用"贴在策略下拉旁；不汇总、不重复。
- 付费来源：速率/额度字段可以留空（平台不会限制你），留空即表示"不做本地限制"。

### 5.3 准入判定（能不能发）

- 按手填速率算漏桶时间戳：窗口容量 N、周期 T → 最小间隔 `gap = T / N`；维护 `nextSlotAt`：
  - 可发条件：`now >= nextSlotAt`
  - 发送后：`nextSlotAt = max(nextSlotAt, now) + gap`
  - 效果：突发不越界，空闲不累积成一次性爆发。
- 速率 `0` → 跳过准入，永远可发。
- 并发型（`concurrency = N`）：当前在途数 ≥ N 即视为不可用（不排队，换下一个源）。
- token 型（tpm/tpd）：以响应 `usage` 回填；放行前按预估预扣，返回后按实际多退少补。
- 流式按"发出时刻"计时（长生成不把速率算钝）。
- 可选额度（`quota`）用尽 → 该源不可用，直到日/月重置（若 `period=none` 则需人工恢复）。

### 5.4 用量与统计（后台）

- 每次调用记录：时间、请求模型、命中来源、真实模型、状态（成功/换源/失败）、耗时、tokens、是否 fallback 到付费、是否探测请求。
- 统计视图：按天/按来源的调用量、成功率、错误类型分布、换源次数（**不按访问口令拆分**，自用无意义）。
- **探测请求单独标记**，不计入客户端用量（付费源的探测默认关闭，避免花钱）。

## 6. 上游失败处理与恢复（本版核心之一）

### 6.1 什么算"上游拒绝/失败"

429 限流、额度耗尽类错误、5xx、超时、连接失败、DNS/TLS 失败、响应格式异常。

**认证类错误（401/403 invalid key）单独处理**：默认一律 `stop_manual`（探测无意义，key 不会自己变好），后台显著提示"需要更换 key"。

### 6.2 三种策略（每个来源可选）

| 策略 | 行为 | 适用 |
|---|---|---|
| `keep_trying`（不停用） | 失败只记日志，来源**保持可用**，下次请求照样可能选到它 | 偶发抖动、或你明确想"一直试" |
| `cooldown_probe`（倒计时检测，**默认**） | 失败 → **该 (来源, 模型)** 进入冷却 → 到期**自动发一次探测请求**（探的就是这个模型）→ 成功则恢复可用，失败则**按等待时长表换到更长的间隔**继续（如此循环，直到额度刷新/恢复为止） | 绝大多数情况；尤其"额度到了/限流中"的场景 |
| `stop_manual`（停用不检测） | 失败 → 停用，**不再自动探测**，直到后台手动启用 | 你已知它长期不可用（欠费、key 失效） |

- **状态粒度：按 (提供商, 上游模型) 各自独立**。同一个提供商下不同模型的额度/限流往往各自独立（典型：ModelScope 上今天这个模型用完了、同家另一个还正常），按提供商标记会把好模型一起拖下水。因此某模型失败只冷却它自己；提供商列表展示**聚合结果**（有一个模型能用就算可用，并显示 `n/m 个模型可用`）。
- 恢复判定是**严格的**：冷却时间到 ≠ 恢复，必须等探测成功（状态回到 `available`）才重新参与路由——避免把"还没验证"的模型当成好的一直用。
- **等待时长是全局的一张表（退避）**，不再按来源各配一个秒数：默认 `[15, 60, 300]` → 失败后 15 秒探、再失败 60 秒、再失败 300 秒、之后一直 300 秒。理由见 §11.1「退避探测」。429 带 `Retry-After` 时取它与当前段的较大值。
- **冷却期间的手动「测试」也算一次失败**（用户裁定 2026-09-11）：它会**把等待表往前推一段**，而不是把倒计时打回第一段；已经在最后一段时就原地重新计时。语义是"你又确认了一次它还没恢复"，所以不该让整张表白排。
- **有些错不值得探测，直接转「需人工」**（用户裁定 2026-09-11）：上游回 400/422（模型名写错、参数被拒）这类**探测也不会好**的错，是配置问题 —— 不进冷却、不排探测，状态直接 `stopped`，原因里带上游原文。404 同理（`All` / 模型组继续换源，但这个模型本身转需人工）。
  - 这是真机踩出来的：配了一个不存在的模型名，上游回 `400 Invalid model id`，旧逻辑却按"倒计时检测"白探了 4 次、还在冷却里，用户明确要求"这种应该报错人工"。
- "一直探测直到恢复"就是额度刷新后自动复活：探测失败 → 换更长的间隔 → 再探测，不会停（除非触发探测次数上限转"需人工"）。
- **没有单独的"是否探测"开关**：探测与否由策略本身决定 —— 只有选『倒计时检测』的来源会被探测。免费来源建议『倒计时检测』；付费来源建议『停用不检测』（探测会花钱）。

### 6.3 探测怎么做

- 探测哪个模型：**状态本身就是 (来源, 模型) 级的，所以"冷却的那一行就是它"** —— 直接探这个模型（无需再猜）；如果该模型已从配置里删掉，这条状态会被复位清理。发一次**极小请求**：固定短 prompt + `max_tokens = 1`。
- 判定标准：**HTTP 成功即视为恢复**（不去解析响应内容）。翻译型协议（anthropic / CF）额外检查"HTTP 200 但 body 里说失败"的情况。
- 探测结果写入后台调用日志（标记 `is_probe=1`），便于你判断这个源到底怎么了。
- **探测只由策略触发**：选『倒计时检测』的来源才会被探测（免费来源的推荐选择）；选『停用不检测』（付费来源推荐，避费）或『不停用』的来源不会被探测。
- **探测间隔 = 等待时长表**：第 1 段（默认 15 秒）→ 第 2 段（60 秒）→ 第 3 段（300 秒）→ 之后一直用最后一段。探测循环每秒扫描一次，到点就探；单次探测是 `max_tokens=1` 的极小请求，开销可忽略（CF 上约 0.5 neurons/次）。

### 6.4 停用期间的展示

后台"来源状态"列显示：`可用` / `冷却中（剩 3 分 12 秒，下次探测时间）` / `已停用（原因：认证失败，需更换 key）` / `已停用（手动）` / `额度用尽（12:00 重置）`。

## 7. 选源算法与付费兜底

### 7.1 算法（可用性优先，其次用户排序）

```
0. 解析请求里的 model（见 §3.5）：
     All                       → 候选 = 全部启用来源下的启用模型，进入第 1 步
     ModelGroup/<组名>          → 候选 = 组内的启用模型，按组内 sort_order（可混免费付费），进入第 2 步
     Free/来源id/模型名         → 候选 = 这一个（pinned，不换源，失败直接报错）
     Pay/来源id/模型名          → 同上，但要求该来源确实是付费来源
     其它（裸名/漏类别前缀/来源错/前缀与免费付费不符/模型错/组不存在）→ 404（文案提示正确格式）
1. 候选顺序：
     All        → 按「All模型顺序」页的拖拽顺序（免费组在前 → 付费兜底组），组内按模型条目的 sort_order
     模型组      → 按组内条目的 sort_order（不吃"免费在前"那套）
2. 过滤：剔除"此刻不可用"的候选
     不可用 = 冷却中 / 已停用 / 额度用尽 / 已达本地限速 / 手动禁用
3. All / 模型组：按顺序逐个试（All 免费排前面 ⇒ 免费不行自然落到付费）# ← 付费兜底就是这一步
   pinned：只有一个候选
4. 首选源失败(首字节前) → 顺次尝试下一个候选（仅 All/模型组；流式则必须在首字节前）
5. 虚拟名字全部失败 → 统一 503 + 最早恢复时间；pinned 失败 → 按 §3.4 的规则单独报错
```

- **不做自动打分/智能轮换**：顺序完全由用户在拖拽页决定。
- `All` 的免费组与付费组不交叉：付费来源只有在免费组**全部不可用**时才会被选中（符合基准第 7 条）。**模型组不受这条约束** —— 组里怎么排就怎么试，这是模型组存在的意义。
- **虚拟名字的候选包含多个模型**（不只是同名模型）：这是"一个 api 调用所有 api"的落点——哪个来源现在能用就用哪个。
- pinned 请求**绝不**降级到别的来源：宁可报错，也不让用户以为"用的是我要的那家"。

### 7.2 付费兜底的可观测性

- 每次落到付费来源，UI/日志标记 `paid-fallback`，统计里单列一行"今天有多少次是因免费全挂而花了钱"。
- 付费来源的**速率/额度字段是可选**：平台通常不会限制你（巴不得你多用），本地限制只是防误烧的自保手段，**默认留空**；想设就设，不设也不影响它被使用。

- 日志默认保留 30 天（可配），定期清理。

### 8.1 凭据加密与存储（**全用现成库，不手写密码学/存储**）

用户要求：上游 apiKey 与访问口令都不能明文落库；并且**尽量用成熟库，不要自己造加密或存储层**。

**加密与哈希 —— 只调库，不自研算法：**

| 用途 | 用什么 | 说明 |
|---|---|---|
| 上游 apiKey 加密 | **`libsodium-wrappers`** 的 `crypto_secretbox_easy`（NaCl，经审计的库）| 一行调用完成认证加密，nonce 与密钥由库处理；存 `nonce + 密文` 的 base64 即可，不用自己拼 GCM 参数；界面只回显掩码（如 `sk-***3f9`）|
| 凭据加密 | **`libsodium-wrappers`**（secretbox） | 一个库管全部凭据（上游 key / 下游口令 / 管理口令）；加解密都走它，不自研 |
| 主密钥保管 | 环境变量 **`APP_SECRET`**（配 `dotenv` 读取）或 Docker secrets | 密钥不落库、不进镜像、不进 git |

**存储层 —— 用库，不手写 SQL 引擎与迁移：**

| 方案 | 用什么 | 说明 |
|---|---|---|
| ① **推荐** | **better-sqlite3** + **Knex** | 表结构与迁移用 Knex 的 schema builder / `knex migrate` 管理（不手写 SQL 引擎与迁移脚本）；敏感字段写入前过一遍上面的加密库 |
| ② 整库加密 | **better-sqlite3-multiple-ciphers**（SQLCipher 的 Node 绑定）| 打开库时给口令即可，整个 db 文件加密；SQL 与业务代码几乎不变 |
| ③ 最简 | **better-sqlite3** + 上游 key 存 `data/secrets.json`（权限 600）| key 完全不进库；其余配置照常入库 |

- **主密钥不必用户填**（用户裁定 2026-09-12："app_secret 没有就随机生成吧。都 docker 了讲的不就是开箱即用"）：
  顺序是「环境变量 `APP_SECRET` → 数据目录里的 `app-secret.key` → 都没有就随机生成并落盘」，
  见 `src/appSecret.js`。存在数据目录旁边是因为加密模块要在**数据库迁移之前**就绪（迁移可能写入加密字段），
  存库会变成先有鸡还是先有蛋；跟库一起挂卷/备份，语义也最清楚。
  代价如实说：密钥和密文躺在一起，拿到文件就能解开上游 key —— 和过去把 `.env` 放在项目里同一风险等级，
  换来的是"装完就能跑"。想更严就显式设 `APP_SECRET`（注入密钥、或只把密钥文件挂进来）。
  两个来源同时存在且不一致时会 WARN 提醒（那通常意味着换了密钥，旧的上游 key 会解不开）。
  只剩一种错误要拦：显式填了个 <16 字符的。
- 主密钥丢失 = 已存 apiKey 无法解密：文档明示，恢复路径 = 重新填写各家 key。
- 原则：**不自研加密算法、不手写数据库引擎/迁移**，只用上表中经过广泛使用的库。

登录方式：管理员口令（首次启动设置或环境变量），登录后写 session cookie。前端为**原生 HTML/CSS/JS（零框架）**，拖拽用原生 Drag & Drop。本应用**不内置 HTTPS**：若要让内网之外访问，请自行套 Cloudflare Tunnel 或 TLS 反代。

| **提供商** | 增删改提供商（**弹层表单**，右下角"取消 / 添加"）：id、名称、baseUrl、apiKey（打码）、适配器、速率（rpm）、拒绝策略、倒计时秒数、免费/付费、启用；字段级提示 |

| **首次设置** | 啥也没有时（新装 / 刚跑过 `scripts/reset-credentials.js`）显示这一屏：设**管理密码** + **下游 apikey**。口令那格已有值时显示成 `sk-****` + 「更改」按钮，**留空提交 = 保持原样**（不会顺手换掉正在用的口令）。完成后自动登录。**只允许从本机/内网发起**（用 TCP 对端地址判定，不信 `X-Forwarded-For`）|
| **密码** | 两块：**后台管理密码**（掩码 + 「更改密码」弹窗）｜**下游请求 apikey**（`sk-****` 掩码 + **复制** + 「更改 apikey」弹窗）。合并了原来的「访问口令」页和设置页里的管理密码块（用户裁定 2026-09-11）|
| **日志** | 调用流水（计划按来源/状态/模型/时间筛选；当前界面只有最近 200 条列表，API 已支持筛选参数）|
| **设置** | 允许无口令访问开关、假数据端点开关、**倒计时检测次数上限**、**等待时长表（退避）**、调用日志保留天数、**时区（UTC 偏移小时）**、`All`/模型组的上下文长度 |

**管理端限内网（用户裁定 2026-09-11；2026-09-13 改为不可关闭）**：`/admin`、`/api/admin/*`（唯一例外是 `/api/admin/setup/status`，它专门用来把"为什么进不去"告诉前端）、`/api/client-log` 只允许**本机/内网来源**，公网来源一律 `403`（`code: admin_local_only`）；`/v1/*` 不受影响。

放行的**唯一**开关是环境变量 `ALLOW_PUBLIC_INTERNET`（严格只认 `true` / `false`，大小写不敏感；不认 / 没配 = 内置默认 `false`）。用户 2026-09-13 要求把后台那个「管理端限内网」设置项（`admin_local_only`）删掉了 —— 少一层间接，也就不存在"点了开关没反应"这种要猜的情况。判定入口只有 `src/auth.js` 的 `publicSourceAllowed()` 一个。

- 理由：后台和 `/v1` 是**同一个端口**，用户把 API 开放出去会顺带把后台也端到公网 —— 这不是用户粗心，是这东西的默认形态本身有坑。所以挡在产品层，而不是写进文档指望部署的人记得。
- 判定用 **TCP 对端地址**（`src/net.js`），**不信 `X-Forwarded-For`**（应用开了 `trust proxy`，否则随便带个头就能把自己伪装成本机）；反代装在本机时对端就是 `127.0.0.1`，照样放行。**IPv6 与本机/内网的完整口径见 §10.1**（`::1`、`fc00::/7`、`fe80::/10`、双栈下 IPv4 客户端的 `::ffff:x.x.x.x` 都算内网；公网 IPv6 与公网 IPv4 同等待遇）。
- 判定发生在**鉴权之前**：公网来源即使拿到会话 cookie 也用不了后台（这也是"没有 HTTPS 时 cookie 会明文传输"那条风险的兜底）。
- 公网来源打开 `/admin` 时页面照常出来，由前端在登录页写明「管理端只允许从本机或内网访问（你在 x.x.x.x）。要在外面管理，请从内网访问或用 SSH 隧道进来。」——不让人白输一遍密码再吃 403。

**失败锁定（用户裁定 2026-09-15）**：后台登录和 `/v1/*` 用同一个 `createFailureGuard`（`src/limiter.js`），各记各的账：

| 项 | 值 |
|---|---|
| 阈值 | 同一个来源 **连续失败 5 次** |
| 第一次锁多久 | **5 分钟**（`baseLockMs`）|
| 之后 | 每再失败一次**翻倍**：10 → 20 → 40 分钟，**1 小时封顶**（`maxLockMs`）|
| 忘掉 | **24 小时**没有新的失败就重置（`forgettingMs`）|
| 成功 | **立刻解禁**（计数清零）|
| 计数键 | 来源 IP（`net.clientAddress`）|

- 后台登录的"失败" = 口令不对；`/v1/*` 的"失败" = 响应状态码 ≥ 400（口令不对 / 模型名写错 / 来源全挂 / 上游报错都算），2xx 算成功。`/v1` 这个判断挂在响应结束（`res.on('finish')`）上，流式请求一样算。被这道闸自己挡掉的 429 **不计数**（否则每被挡一次就翻倍，永远出不来）。
- 命中时返回 `429` + `Retry-After`（秒），`error.code` 是 `too_many_failures`。
- **故意不做全局兜底**：原来有一条"1 分钟内全局失败 100 次就把所有 IP 一起锁 1 分钟"（防换 IP 绕），用户 2026-09-15 要求删掉 —— 原话大意是：会不计成本换一堆 IP 来打的人，代价已经高到离谱，真碰上就给他用。于是不再有会误伤正常用户的全局封锁。`enforceCap()` 只是**内存**上限（Map 超过 1000 条就淘汰最久没失败过的记录），不减谁的刑期。
- 为什么要有：客户端撞错（模型名写错、上游全挂）时会在一个循环里反复打 —— 每个请求都要查库选源、写一行调用日志、往 stderr 打一行，不限速就是白烧资源（磁盘最先撑爆的是容器日志）。

**管理口令的存储（用户裁定 2026-09-15）**：从 argon2id 哈希改成**和下游 apikey 完全同一套** —— libsodium secretbox 可逆密文（键名 `admin_password_enc`），校验改成解密 + 常量时间比对。

- 理由：argon2 每次校验要 **64 MiB 内存 + 3 轮计算**，而这条路的暴力破解本来就被上面的失败锁定挡着（5 次失败锁 5 分钟），换来的一点收益不值这个成本；顺带**少一个要编译的原生模块**（argon2 已从 `package.json` 移除，镜像构建也更省事）。
- 代价如实写：**数据目录 + `APP_SECRET` 一起泄露 = 管理口令明文**。那两样凑齐本来就已经等于下游 apikey 明文（§3.2），所以没有新开口子。界面照旧只让"改"、不显示明文。
- **老库（只有 argon2 哈希 `admin_password_hash`）**：新版本读不出来，此时 `passwordState()` 报 `legacy`。**故意不当作"没设过"** —— 否则内网里谁先打开 `/admin` 谁就能把后台认领走，静默降级比进不去严重得多。表现：`needsSetup` 仍为 false（首次设置页不出现、`/setup` 回 409），登录一律 401 且错误里给出处理命令；启动时用 error 级别日志说清楚。出路只有 `scripts/reset-credentials.js`（它把新旧两个键一起清掉）。

> 「统计」页（趋势图、来源排行、错误类型分布、换源率、付费兜底支出估算）**尚未实现**，当前只有主页那排今日数据、来源状态和日志页。

**概览卡的口径（都是"今日"）**：

| 卡片 | 怎么算 | 为什么这么定 |
|---|---|---|
| 今日请求 / 失败次数 | `call_log` 当天行数；失败 = `status='fail'` 且 `error_type <> 'client_abort'` | **客户端自己取消不算失败**，否则你每打断一次流，失败数就 +1 |
| 免费 token / 付费 token | `SUM(prompt_tokens + completion_tokens)`，按 `is_paid_fallback` 分组，**今天所有请求全加**（成功的、失败的、后台「测试」、倒计时探测都算） | 用**写日志那一刻**记下的"命中的是不是付费来源"，而不是事后 join `providers.is_paid` —— 来源属性后来被改或删掉，历史统计不该跟着变。探测也是真打上游，CF 那类按 token 计费的就该算进去 |
| 可用模型 | `可用 / 总数`；可用 = 提供商启用 且 模型启用 且状态不是 `stopped` | **冷却中 / 额度用尽 / 本地限速都算可用**（它们会自己恢复，「故障（需人工）」才是坏了）—— 用户明确定的口径 |
| （今天＝哪一天） | 后台设置 `utc_offset_hours`（**默认 0 = UTC**），卡片上只在非 UTC 时才标 `· UTC+8` | 见下面「时区」一节 |

**时区（用户裁定 2026-09-12）**：原话"还是让用户自己设置吧。默认 utc 啥也不加。有些 linux 可能没设置过，还保留着默认的 utc。"

- 设置项 `utc_offset_hours`（后台「设置」页，`-12 ~ +14`，允许小数如 `5.5` = UTC+5:30），**默认 0 = UTC，卡片上不加任何后缀**；改成 8 才显示 `今日请求 · UTC+8`。

- **它管两件事，且必须是同一个零点**：① 主页「今日」的统计；② `rpd`/`tpd` **日额度窗口的重置时刻**（`rateState.windowStartFor`）。以前这两处各用各的（都是进程本地时区），改完统一走 `timezone.dayStart()`。测试 M4-13 里有一条断言专门钉这个一致性。
- 改完**立刻生效**（不用重启）：设置接口写库的同时更新进程内缓存；启动时读一次（`timezone.loadOffsetHours()`）。

**两张日志表都有 `token（入/出）` 一列**（主页「最近调用」+「日志」页）：一次请求自己的用量，悬停看精确值。**显示用紧凑写法**（用户 2026-09-12 指定）：`46447` → `46.4k`、`6789372` → `6.8m`（再往上 `b`；`999950` 会进位成 `1.0m` 而不是 `1000.0k`），精确数字放 `title` 里。上游没返回 `usage` 时显示 `-` 而不是 `0` —— `0` 是"真没用"，`-` 是"上游没说"，排查时是完全不同的两件事。`probe.js` 里探测/测试的成功路径也补上了用量记账（以前这类行的 token 一直是 NULL，会让"今日 token"少算）。

## 10. 部署（Linux）

- **目标环境：Debian 12 + Docker（Compose v2）**。交付物 = `docker-compose.yml` + 镜像构建文件；`docker compose up -d` 即可。容器设 `restart: unless-stopped`（开机与崩溃自动拉起），**不需要写 systemd unit**；网络模式默认 **`host`**（见 §10.1）。
- 服务容器：`app`（Node 服务）+ 可选 `caddy`（你想加 TLS 反代时用）。
- 数据卷：`./data:/app/data`（SQLite 数据库 + 日志）。备份 = 打包 data 目录。
- **默认双栈监听**（`::`）：`/v1` 要对客户端开放，服务器有 IPv6 地址时客户端直接用 `http://[IPv6]:8787/v1` 就行，不用另配。**管理后台另有来源闸**（§9，默认就是限内网、后台里没有开关）：非本机/内网来源访问 `/admin` 与 `/api/admin/*` 一律 403，所以"监听所有地址"不等于把后台端出去。想只监听本机，用环境变量 `BIND=127.0.0.1`。

- **不内置 HTTPS**（用户裁定）：默认 HTTP，面向**内网 / 自有服务器**。若确实需要公网访问：
  1. 推荐 **Cloudflare Tunnel**（零证书配置、不用开放入站端口）；
  2. 或 Caddy / Nginx 反代 + 在线证书。
  **切勿把明文端口直接暴露到公网**：访问口令与对话内容都会明文传输。
- 单实例假设：定时任务在进程内，**不要同时起两个容器**（否则探测会重复、限速计数会分裂）；启动时检测并拒绝第二个实例。

### 10.1 监听地址与 IPv6（用户 2026-09-12 的要求）

> 原话："服务器有 ipv6 地址，网页后台和 api 调用都应该支持 ipv6。"

`BIND` 的语义（`src/index.js` 的 `bindCandidates()`）：

| 填什么 | 行为 |
|---|---|
| 留空（默认） | **所有地址**：先试双栈 `::`，绑不上（这台机器没启用 IPv6）就自动退回 `0.0.0.0` |
| `0.0.0.0` | 同上 —— 写它的人想表达的是"监听所有地址"，不是"只要 IPv4"。老 `.env` 里基本都是这个值，**升级后自动吃到 IPv6**，不用改配置 |
| 具体地址（`127.0.0.1`、`192.168.1.5`、`::1`、`fd00::1`） | **只监听它**；绑不上就报错退出（写死的地址不悄悄替换） |

为什么双栈这件事**必须**和来源判定一起改（`src/net.js`）：

- 双栈下 IPv4 客户端的对端地址会变成 **IPv4-mapped**（`::ffff:192.168.1.5`）。如果判定只认点分十进制，那么"从局域网用 IPv4 打开后台"会被当成公网 → **管理端来源闸把管理员自己挡在外面**（这正是最容易踩的坑，用 `test/m8.test.js` 的 M8-2 钉住）。
- 公网 IPv6（`2001:...`、`2408:...`、`2001:db8::/32`）**不算内网** → 和公网 IPv4 一样 403（M8-4）。
- 内网口径补全：`::1`（含 `0:0:0:0:0:0:0:1`、`[::1]` 写法）、`fc00::/7`（唯一本地）、`fe80::/10`（链路本地，含 `%eth0` 这种 zone）、`::ffff:7f00:1` 这种"十六进制写法"的 mapped 地址（有些协议栈会这么给）。

其它配套：

- 启动日志会把**实际绑定的地址**和 IPv6 入口打出来（`{"bind":"::","dualStack":true,"ipv6":"http://[::1]:8787"}`）；退回 IPv4 时给一句 `note` 说明原因。
- IPv6 字面量拼进 URL 必须加方括号（`http://[::1]:8787`），`net.hostForUrl()` 统一处理。
- 本地实测（2026-09-12）：本机同时有公网 IPv6（`2408:...`），`http://[::1]:8787` 与 `http://[2408:...]:8787` 上的 `/healthz`、`/v1/models`、`/admin` 全部 200；而用公网 IPv6 地址访问 `/api/admin/*` → **403**（来源判定认出它是公网，`clientIp` 就是那个公网地址）。
- **已知取舍**：没有"所有 IPv4 但不要 IPv6"这个组合。实践中影响很小——从 IPv6 进来的公网客户端本来就被管理端闸挡在后台外；真要拦网络层，用 ip6tables/防火墙。
- **Docker 用 `host` 网络模式**（compose 默认，用户 2026-09-12 提出）：容器共享宿主机网络栈，所以两个问题一起没了 ——
  1) **IPv6 零配置**：容器里绑双栈就等于绑在宿主机上，不需要给 daemon 开 `ipv6`/`ip6tables`、也不用写 `"[::]:8787:8787"` 这类发布语法；
  2) **源 IP 保真**：管理端来源闸靠 TCP 对端地址判断，而 bridge 模式在 rootless Docker（slirp4netns）之类环境下会把所有外部来源记成网关地址（`10.0.2.2` / `172.17.0.1`）→ 公网客户端被当成内网，**闸会悄悄失效**。host 模式下源 IP 一定是真的。
  - 代价：容器独占宿主机的端口（冲突就改 `PORT`）；Docker Desktop 对 host 模式支持有限，非 Linux 平台请用 bridge 写法。
  - **自查方法**（不管哪种模式都该做一次）：从公网 `curl http://<地址>:8787/api/admin/setup/status`，看 `clientIp` 是不是真实公网地址；显示网关地址就说明源 IP 被 Docker 吃了。参考 [Docker IPv6 端口发布](https://OneUptime.com/blog/post/2026-03-20-docker-port-ipv6/view)。

**M2（速率准入 + 倒计时探测）**
- 速率填写框**真正参与判定**：`rpm`/`tpm` 用**漏桶**平滑放行（`gap = 窗口/N`）；`rpd`/`tpd` 用**计数闸门**（用满即停、窗口重置恢复，日窗口按本地自然日）；`concurrency` 用进程内并发计数；`0` 或留空 = 不做本地限制。
- 429 时按上游 `Retry-After` 把下一次可用时刻推后（校准），并按所选策略改来源状态。
- **倒计时探测循环（按模型）**：状态是 (来源, 模型) 级的，处于"冷却中"且冷却到期的**那个模型**会被自动发一次极小请求（`max_tokens=1`）——成功则它恢复可用，失败则按**等待时长表（退避）**换到更长的间隔继续等（**额度刷新后自动复活**，不会停）；同家其它模型完全不受影响。探测记录单独入库（`is_probe=1`），不混入正常调用。后台「立即探测」会探测该来源下所有启用的模型。**等待时长表**（全局设置，默认 `[15, 60, 300]`，可加/删段，上限 20 段）：第 N 段 = 第 N 次探测之前等多久，最后一段带"后续"含义；429 带 `Retry-After` 时取它与当前段的较大值。**探测次数上限**（全局设置「倒计时检测次数上限」，默认 10；填 0 = 一直探测）：某个 (来源, 模型) **连续探测失败**达到上限后，**停止自动探测、转为 `stopped`**（界面显示「故障（需人工）」），避免对着一个修不好的模型一直发请求；探测成功或人工「恢复可用」会把计数清零。估算：把等待表按次数累加 ≈ 放弃前的最长等待时间（默认 15+60+300×8 ≈ 41 分钟）——若某源的额度按天刷新，要把上限调大（如 288 ≈ 24 小时）或设 0。**探测循环每秒扫描一次**（没有全局间隔设置），具体重测时刻由等待表决定——时间由后端精确掌握。
- **为什么用表而不是固定秒数**（用户裁定 2026-09-11）：上游不会告诉我们什么时候能好（实测 ModelScope/DeepSeek 连限流响应头都不发），只能探测；写死一个值必然是猜（猜小了白打上游、猜大了抖动也要瞎等）。退避把"猜一个正确的秒数"变成"不用猜"：从短间隔起步、逐步拉长，让上游自己告诉我们。这也正是此前被撤回的"按错误类型的冷却表"要解决的问题，但**不需要判断错误类型**，也不新增每来源的配置项。

**IPv6 支持**（2026-09-12，用户要求："服务器有 ipv6 地址，网页后台和 api 调用都应该支持 ipv6"）

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| **口令泄露 → 别人也能用你的免费额度** | 口令只存哈希、可一键更换；默认禁止无口令访问；可选 IP 白名单（内网固定 IP 场景就够用）|
| **不做 HTTPS 的风险** | 默认只在内网/自有服务器使用；文档明确"不要把明文端口暴露到公网"；需要公网请自行套 Cloudflare Tunnel 或 TLS 反代 |
| 速率填 0 反复撞限流 → 上游封号 | §4.1 免费源的字段级提示；默认策略 `cooldown_probe`；探测间隔可调（免费源限流窗口长就把倒计时调大）|
| **主密钥丢失 → 已存 apiKey 无法解密** | 启动校验 + 明确指引；文档提示备份 `APP_SECRET`（`.env` 或 Docker secrets）；恢复路径 = 重新填写各家 key |
| 上游额度/政策变动 | 全部配置化；不需要改代码；后台直接调速率或停用 |
| 静默转付费（免费层超额自动计费） | 免费来源**不要绑卡**；本地额度字段可设硬上限；`paid-fallback` 单列统计便于发现异常 |
| 探测本身花钱/花额度 | 付费来源默认不探测；探测用 `max_tokens=1` 极小请求 |
| 只做 2 个端点导致客户端不兼容 | usage/billing/credits 给假数据；其余返回标准 404；文档列出兼容性说明 |
| 单实例假设被打破（起了两个容器） | 文档明示；启动时检测锁文件/DB 占用并拒绝启动第二个实例 |
| 本地计量与上游实际不一致 | 以 L2 错误为权威停止信号；本地只做提前止损 |
| 时区导致"每天"重置错位 | **已实现**：后台设置 `utc_offset_hours`（默认 0 = UTC），"今日"统计与 rpd/tpd 日额度共用同一个零点（§9） |

## 13. 技术选型定案（已无未决项）

**本轮已定**：口令式极简鉴权（不做限流/账号/统计）；不做 HTTPS；前端零框架（原生 HTML/CSS/JS）；**探测不是独立开关**，由策略三选一决定；**提示改为字段级内联、不汇总**；加密与存储全用现成库；部署目标 **Debian 12 + Docker**；**默认双栈监听**（IPv4 + IPv6 同一端口，见 §10.1）。

| 项 | 定案 | 说明 |
|---|---|---|
| 后端语言 | **纯 JavaScript**（Node.js 20）| 用户明确不写 TS；不引构建步骤 |
| Web 框架 | **Express** | 中文资料与示例最多、SSE 直接 `res.write()` 最直观、静态托管一行 `express.static`；Fastify 性能更好但此处毫无必要 |
| 数据库 | **better-sqlite3** + **Knex** | Knex 负责查询构建与迁移，不手写 SQL 引擎/迁移脚本 |
| 上游 key 加密 | **libsodium-wrappers**（`crypto_secretbox_easy`）| 一次调用完成认证加密（含 nonce 处理），不用自己拼 GCM 参数 |
| 口令存储 | **`libsodium-wrappers`**（secretbox 可逆密文）+ 常量时间比对 | 和下游口令同一套（原来是 argon2 哈希，2026-09-15 改）；省一个原生模块，也省掉每次 64 MiB 的校验开销 |
| 主密钥 | 环境变量 **`APP_SECRET`** | 不落库、不进镜像 |
| 前端 | 原生 HTML / CSS / JavaScript | 零框架；拖拽排序用原生 Drag & Drop |
| 部署 | **Debian 12 + Docker Compose** | `restart: unless-stopped`；默认双栈监听（IPv4 + IPv6） |

**已定默认值**：探测间隔 300 秒；`keep_trying` 保留但默认不用；假数据端点 3 个（usage / billing/subscription / credits）。

**无未决项 —— 可以直接开工 M0（骨架 + 提供商/模型配置 + `/v1/models` + 非流式 chat）。**
