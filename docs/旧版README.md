# LLM API 聚合网关（服务端版）

一个自用的 LLM API 聚合网关：**一个 API 调用所有 API**。服务端持有各家上游的 key，客户端只用一道访问口令即可连接；上游被限流/报错时静默换源，不把错误抛给客户端。

设计与决策依据见 [`docs/设计文档.md`](docs/设计文档.md)（当前版本 v0.4）。

## 快速开始

**服务器部署（Docker，推荐）**：两步，不用先准备任何东西。

```bash
mkdir -p data && sudo chown -R 10001:10001 data   # 镜像里跑的是非 root（uid 10001）
sudo docker compose up -d --build
# 管理后台： http://<服务器地址>:8787/admin   ← 第一屏是「首次设置」
# 客户端入口：http://<服务器地址>:8787/v1
```

没 Docker 的机器可以用别人打好的镜像包（`docker load`，见下面「部署」§B）。

**本机开发 / 改代码（只用 Node，不需要 Docker）**：

```bash
npm install
npm start
# 管理后台： http://localhost:8787/admin   ← 第一屏是「首次设置」
```

**什么都不用填**：凭据加密主密钥（`APP_SECRET`）缺省会**自动生成**并存到 `data/app-secret.key`
（重启、重建容器都不变，备份 `data/` 目录就够了）；管理密码和下游 apikey 在第一屏的「首次设置」页里设。
想自己管主密钥、或改端口/数据目录，才需要 `cp normal.env.example normal.env` 然后改它（`npm run init` 也是干这个的）。
优先级是 **环境变量 > `normal.env` > 内置默认**（见下面「关键配置项」）。

**首次使用顺序**：启动后打开 `http://<主机>:8787/admin` —— 第一屏就是「**首次设置**」，在那儿设**管理密码**和**下游 apikey**（留空自动生成，`sk-` 会自动补上）。完成后直接进后台 → 「提供商」页添加上游（地址 + apiKey + 速率 + 拒绝策略）→ 在该提供商下添加模型 → 客户端用 `base_url=http://<主机>:8787/v1` + 那个口令调用。客户端的**模型名**照抄「All模型顺序」页或「模型组」页里的那串（见下一节）。

> 忘了管理密码？跑一次 `node scripts/reset-credentials.js`（Docker：`docker exec llm-aggregator node scripts/reset-credentials.js`），
> **不用重启**，刷新 `/admin` 就又回到「首次设置」页 —— 提供商/模型/日志都还在，只清了密码。
> 想只清管理密码、保留下游口令：加 `--keep-key`。
> 首次设置**只允许从本机或内网发起**（防着"谁先扫到端口谁就占了管理密码"），来源判定用 TCP 对端地址、不信 `X-Forwarded-For`。

## 客户端模型名怎么填（下游唯一要关心的事）

请求体里的 `model` 只有四种合法写法，`GET /v1/models` 返回的就是这些：

| 写法 | 例子 | 行为 |
|---|---|---|
| `All` | `All` | **自动选源**：按「All模型顺序」页的顺序（免费在前 → 付费兜底）挨个试，某个来源挂了就换下一个；全都不行 → `503`。日常就填这个 |
| `Free/来源id/模型名` | `Free/modelscope-cn/deepseek-ai/DeepSeek-V4-Flash-0731` | **指定某个免费来源**：不换源。本机速率没到点 → `429`（带 `Retry-After`）；上游报错 → **原样转发**给客户端 |
| `Pay/来源id/模型名` | `Pay/openai-official/gpt-4o-mini` | **指定某个付费来源**：同上 |
| `ModelGroup/组名` | `ModelGroup/便宜优先` | **你自己的兜底链**：按「模型组」页里排的顺序挨个试（可以混免费和付费），全不行 → `503` |

- 各页「模型」列显示的就是**要照抄的完整名字**；`All` 的尝试顺序 = 「All模型顺序」页的拖拽顺序，模型组的顺序 = 它自己页里的拖拽顺序。
- **不带类别前缀的名字（如直接写 `gpt-4o-mini`、或写 `modelscope-cn/xxx`）一律 404**，并提示正确写法——不猜来源，免得你以为是 A 家、其实静默打到了 B 家。
- 前缀**大小写不敏感**（`pay/`、`PAY/` 都认），但对外一律发布规范写法；`auto` 这个名字**已经不用了**（报错会提示你改成 `All`）。
- 上游模型名本身带斜杠没问题（`来源id/` 后面整串都算模型名）。模型**没有**"显示名/别名"这种东西了——一套名字一个含义。
- **响应里的 `model` 字段不篡改**：指定来源时**上游写啥就是啥**（上游没写就没有这个字段）；`All` / 模型组时保持客户端请求的那个名字（不然客户端把响应里的真实模型名回填下一次请求就会 404）。
- **图片（视觉）**：
  - `All` 和每个模型组**永远**对外声明"能收图"（`architecture.input_modalities: ['text','image']`，OpenRouter 那套写法；顶层也发一份）。为什么要"永远"：下游只在拉模型列表时看一眼能力、之后不会动态调整，所以只能先答应下来。
  - **具体模型**（`Free/…` / `Pay/…`）按你在「提供商 → 模型列表」里点的「图片」按钮声明。
  - 真收到带图的请求时，网关**只把候选缩到标了「支持图片理解」的模型**；一个都没有 → **400 `image_not_supported`**（配置问题，等也不会好）；如果标了图的模型此刻都不可用 → **503**（可恢复）。
  - **绝不把图片丢掉再发出去** —— 那样你会收到一个"没看图"的回答，比报错糟得多。
  - 适配器都支持图片：`openai-compatible` 原样透传；`anthropic` 会把 OpenAI 的图片块翻成 Anthropic 的 `image` 块（data URL → base64、http 图片 → url）；`cloudflare-workers-ai` 也在参数白名单里透传。
- **`All` 和每个模型组的条目里会带上下文长度**（`context_length` + `context_window` 两个字段名都发，默认 **256000**，在后台「设置」页可改，填 `0` = 不发布）。客户端靠它决定**什么时候压缩上下文**；[虚拟名字] 会落到任何一个来源，所以这个值要按**所有来源里最窄的那个**填。
  - 为什么重要：客户端不知道窗口时只能用自己的默认值（DSH 是 256k）去攒上下文，撞上窗口更小的来源就会报"上下文超长"。填对了它就会提前压缩，永远不会撞。
  - 参考值：Cloudflare 的 `nemotron-3-120b-a12b` 是 256K（它自己是 256000）；ModelScope 上的 `Qwen3.8-Flash-Next` 原生 262144（可扩展到 1M）；`GLM-5.3-Flash` 和 DeepSeek 的 V4 系列都是 1M。

## 上游协议适配器（3 种，添加提供商时选）

| 适配器 | 什么时候选 | 怎么填 |
|---|---|---|
| `openai-compatible` | 绝大多数平台（ModelScope、NVIDIA NIM、DeepSeek、各家中转……） | baseUrl 填到 `/v1` 那一层，例如 `https://integrate.api.nvidia.com/v1` |
| `anthropic` | Anthropic 官方 API（Claude）或"Anthropic 兼容"的中转 | baseUrl 填 `https://api.anthropic.com/v1`（填到域名也行，会自动补 `/v1/messages`）；模型名填 Claude 的 id，例如 `claude-sonnet-4-5` |
| `cloudflare-workers-ai` | Cloudflare Workers AI | baseUrl 保持 `https://api.cloudflare.com/client/v4`，**再填「账号 ID」**；模型名形如 `@cf/meta/llama-3.1-8b-instruct`（地址里的模型路径）|

选非 OpenAI 协议时，**翻译是自动的**：请求按对方的协议发过去，响应和流式增量都翻回 OpenAI 形状再给客户端。所以客户端那边永远只需要认 OpenAI 那一套。

> **真实性说明**：两个非 OpenAI 适配器都已在**真 key 上跑通**（非流式 + 流式 + 用量采集 + `All` 兜底）。
> - `anthropic` 用的是 **DeepSeek 的 Anthropic 兼容地址**：baseUrl `https://api.deepseek.com/anthropic`、模型 `deepseek-v4-flash`。想试 Anthropic 协议又不想开 Anthropic 账号的话，这家的 key 就够用。
> - `cloudflare-workers-ai` 用的是官方模型 `@cf/nvidia/nemotron-3-120b-a12b`。**注意 CF 有两种返回方言**（经典 `result.response` / 较新模型的 OpenAI 形状 `result.choices[].message`，后者推理内容叫 `reasoning`、正文可能是 `null`），适配器两种都认——这是真机踩出来的坑。

细节说明：

- **anthropic**：`system` 提示词会自动从 messages 里提出来单独放（Anthropic 不允许 system 出现在 messages 里）；相邻同角色的消息会合并（Anthropic 要求 user/assistant 交替）；`max_tokens` 必填，客户端没传就补 4096；`thinking` 块会映射成 `reasoning_content`。**工具调用已支持**（见下一节）。
  - ⚠️ 遇到**推理模型**（如 DeepSeek V4 系列、Claude 带 thinking）：`max_tokens` 要留够，否则 token 全被推理吃掉、`content` 会是空的（这是模型特性，不是转换出问题）。
- **cloudflare-workers-ai**：模型名在 URL 路径里，所以请求体里不会带 `model`；只转发它认识的参数（OpenAI 的扩展字段不带过去，免得被拒）；客户端没传 `max_tokens` 时默认 2048（CF 自己的默认只有 256，太短）；它的错误有时是 **HTTP 200 但 body 里 `success:false`**，这种也按失败处理（会进冷却/换源），失败原因就是 body 里的原文。
  - 另外 CF 也有一个 OpenAI 兼容入口（`https://api.cloudflare.com/client/v4/accounts/<账号>/ai/v1`），想用那个就直接选 `openai-compatible` 并填这个地址，不用这个适配器。
- 三种适配器共用同一套失败处理：429 按 `Retry-After` 校准、失败按策略冷却/停用、冷却到期自动探测（`max_tokens=1` 的最小请求）。探测对翻译型协议同样按对方的形状发。

## 工具调用（function calling）

**三种来源现在都能用**，客户端那侧永远只写 OpenAI 那一套：

| 来源协议 | 怎么实现 | 状态 |
|---|---|---|
| `openai-compatible` | 原样透传（我们不碰 `tools` / `tool_calls`） | ✅ 真 key 验过 |
| `anthropic` | **双向翻译**（见下表） | ✅ 真 key 验过（非流式 / 并行多工具 / 多轮回灌 / 流式碎片） |
| `cloudflare-workers-ai` | 参数白名单里本来就有 `tools`，返回的 `tool_calls` 原样透传 | ✅ 真 key 验过（客户端实测可用）|

Anthropic 那边的结构差异是这样对齐的：

| 环节 | OpenAI 形状 | Anthropic 形状（我们翻译成这个） |
|---|---|---|
| 工具定义 | `tools:[{type:'function',function:{name,description,parameters}}]` | `tools:[{name,description,input_schema}]`（去掉一层包装） |
| 模型要调工具 | `message.tool_calls:[{id,function:{name,arguments}}]` + `finish_reason:'tool_calls'` | `content:[{type:'tool_use',id,name,input}]` + `stop_reason:'tool_use'` |
| 工具结果回灌 | 单独消息 `{role:'tool', tool_call_id, content}` | **并进 user 消息**：`{role:'user',content:[{type:'tool_result',tool_use_id,content}]}` |
| 参数 | `arguments` 是 **JSON 字符串** | `input` 是**对象**（我们来 parse / stringify） |
| 并行调用 | `delta.tool_calls[].index` 碎片交错 | `content_block_start` + `input_json_delta` 块事件流 |
| 选哪个工具 | `tool_choice:'auto'/'required'/'none'/{函数}` | `tool_choice:{type:'auto'/'any'/'none'/'tool',name}`（`parallel_tool_calls:false` → `disable_parallel_tool_use`）|

已知边界（会明确报错、不会静默出错）：

- **思考块签名回放 —— 明确不做**（用户裁定 2026-09-11）。背景：Anthropic 开扩展思考时要求下一轮把上一轮那个带 `signature` 的 thinking 块原样带回，否则 400；而 OpenAI 客户端那侧没有"回传思考"的概念，块到客户端就丢了，要做就得在服务端按 `tool_use.id` 缓存思考块、下一轮再贴回去。
  **不做的理由**：用 Anthropic 协议的上游本来就少，其中"强制开思考"的更少，再叠加"严格校验签名"就极少了；而且真踩到时是**上游明确的 400**（日志里直接看得到），不是静默出错。实测 DeepSeek 的 Anthropic 端点会带 `signature` 但**不要求回放**（多轮工具循环正常）；Claude 官方默认不开 thinking，我们根本不发 `thinking`，所以拿不到思考块、也就碰不到。真遇到了再补这套缓存。
- 客户端发来的 `thinking` / `reasoning_effort` 之类的参数**不会转发给 Anthropic**（我们不发 `thinking`，所以 Claude 不会开扩展思考）。

| **DSH 自己跑在本平台上（agent 端到端）** | — | ✅ | 30 分钟内 17 次调用全 ok、零降级；工具循环正常；含一条 40 万 token 输入的请求 |
| Docker 镜像构建 | — | ❌ **没验过** | 本机没装 Docker，只在"模拟容器环境"下跑过一遍启动流程 |
| 思考块签名回放 | — | ⛔ **已裁定不做** | 见上一节"已知边界" |

## 速率填写框（只有一个：rpm）

每个提供商只填**一个数字**：每分钟允许的请求数。

| 填法 | 行为 |
|---|---|
| `40` | 每 1.5 秒放行一个请求（漏桶平滑）——**给慢速源用的**，不会突发撞限流 |
| `0` 或留空 | **不做本地限制**（永远算可用）；适合限速动态、只能"试试能不能用"的平台 |
| 付费来源 | 可以不填（平台通常不限你，本地限制只是防误烧） |

> 免费来源填 `0` 时，后台会在**速率框旁边**给出提示；免费来源把策略选成"不停用"时，会在**策略下拉框旁边**给出提示（两条各自独立，不汇总、不重复）。
> 后端本身还支持 `rpd/tpd/tpm/concurrency` 这些窗口类型（代码里保留、测试覆盖），但界面按你的要求只暴露 rpm。

## 部署到 Debian 12 服务器

两条路，挑一条。**都不需要准备配置文件**（主密钥自动生成、管理密码在网页上设）。

### A) 源码在服务器上构建

```bash
# 服务器上需要 Docker 与 compose 插件
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker

# 把代码放上去（git clone 或解包 tar），然后：
cd nszzj-free-llm-aggregator
mkdir -p data && sudo chown -R 10001:10001 data     # 镜像里是非 root（uid 10001），数据目录得归它
sudo docker compose up -d --build                    # 数据落在 ./data，容器 restart: unless-stopped 会自动拉起
```

> **文件权限**（审计 M7）：`data/` 里有数据库和主密钥，别让它对同机器其他用户可读可写。
> `chmod 700 data`（新建时程序已经按 0700 建目录），`normal.env` 同理（里面有主密钥的话）。
>
> **反代 / Docker bridge**（审计 H1）：管理端只允许"本机或内网**直连**"。如果你在中间放了反代、
> 或用的是 bridge 网络（源 IP 会被抹成 172.17.0.1 / 10.0.2.2），管理端会**默认拒绝**并告诉你怎么修 ——
> 把那个地址写进 `ADMIN_TRUSTED_PEERS`（逗号分隔，支持 CIDR）即可。host 网络模式没有这个问题。

### B) 用别人构建好的镜像包（不 build、不联网装依赖）

在**任意一台有 Docker 的机器**上打一次包：

```bash
npm run image        # = node scripts/build-image.js：构建 + 导出到 dist/
# 产出：dist/nszzj-free-llm-aggregator-<版本>-<架构>.tar.gz + dist/docker-compose.yml + dist/部署说明.txt
```

把 `dist/` 整个目录发给别人（或者拷到服务器），然后：

```bash
docker load < nszzj-free-llm-aggregator-<版本>-<架构>.tar.gz
docker compose up -d
```

- 镜像包是**分架构**的（x86_64 / aarch64），在哪种架构上构建的就只能在哪种上跑。
- 没装 Docker 的机器也能用 `node scripts/build-image.js --files-only` 只生成配套的 compose + 说明文件。
- 升级：`docker load` 新包 → `docker compose up -d`（数据库自动迁移）。

### 起好之后

打开 `http://<服务器地址>:8787/admin` → 第一屏「首次设置」→ 设管理密码 + 下游 apikey。

- 数据与备份：全部状态在 `./data`（SQLite + `app-secret.key`）。**备份 = 打包 `./data` 目录**。
  `app-secret.key` 是凭据加密主密钥（首次启动自动生成），**删了它已存的上游 key 就解不开**。
- **网络模式用 `host`**（compose 里已经这么写了），两个理由：
  1. **IPv6 零配置**：容器里绑双栈就等于绑在宿主机上，宿主机的 IPv4 / IPv6 直接可用，不用给 Docker daemon 开 `ipv6`/`ip6tables`，也不用写 `"[::]:8787:8787"` 那种发布语法；
  2. **源 IP 保真**：管理端的「只允许本机/内网访问」闸靠 TCP 对端地址判断。bridge 模式下源 IP 一般也是真的，但 rootless Docker（slirp4netns）之类会把所有外部来源记成网关地址（`10.0.2.2` / `172.17.0.1`）→ 那些公网客户端会被当成内网，**闸会悄悄失效**。host 模式没这个问题。
  代价：容器独占宿主机的 `8787`（冲突就改 `PORT`）。
  - 自查源 IP：从公网 `curl http://<你的地址>:8787/api/admin/setup/status`，看返回的 `clientIp` 是不是你真实的公网地址。显示 `172.17.0.1`、`10.0.2.2` 就说明被 Docker 吃了。
- 端口：默认 `8787`，**默认双栈监听**（`::`）—— IPv4 和 IPv6 用同一个端口，服务器有 IPv6 地址时直接用 `http://[你的IPv6地址]:8787/v1` 就行；这台机器没有 IPv6 时会自动退回只监听 IPv4。**管理后台默认只允许本机/内网来源**（见「后台交互」一节），`/v1/*` 对外开放不受影响。
- **不要起两个容器**：定时任务在进程内，起两个会导致限速计数分裂。
- **HTTPS**：本应用不内置 TLS。默认面向内网；若要公网访问，请自行套 **Cloudflare Tunnel**（推荐，零证书配置）或 Caddy/Nginx 反代。**不要把明文端口直接暴露到公网**（`/v1` 的访问口令是 Bearer、没有 cookie 问题，但后台的会话 cookie 在没有 TLS 的情况下会被同网络的人捞走 —— 好在管理端默认就挡住公网来源了）。
- 镜像用 `node:22-bookworm-slim`（`better-sqlite3` v13 要求 Node ≥ 22，本地开发也请用 Node 22/24）。
- 忘了管理密码：`docker exec llm-aggregator node scripts/reset-credentials.js`（脚本已打进镜像），不用重启容器，刷新 `/admin` 重新设置。
- 常见排查：`sudo docker compose logs -f` 看启动日志；`sudo docker compose exec aggregator node -e "fetch('http://127.0.0.1:8787/healthz').then(r=>r.text()).then(console.log)"` 看健康检查。**首次装完什么都不用配** —— 启动日志**开头**就会打一张「每个配置值从哪来」的表（环境变量 / `normal.env` / 内置默认），以及主密钥的来源。改了配置不生效时，看这张表就知道是不是被环境变量盖掉了，不用猜。

## 关键配置项（`normal.env` 或环境变量）

配置有**三层**，优先用上面那层：

| 层 | 在哪改 | 说明 |
|---|---|---|
| 1. **环境变量** | `docker-compose.yml` 的 `environment:` 段；或临时 `PORT=9000 docker compose up -d` | 改起来最方便，**优先用它** |
| 2. **`normal.env` 文件** | 项目根目录（`npm run init` 生成，或从 `normal.env.example` 复制一份改名） | 没设环境变量时的**保底** |
| 3. **内置默认值** | 代码里 | 上面都没有（或都不认）才用 |

> - ⚠ **Docker 里第 2 层是空的**：镜像没打进 `normal.env`、compose 也没挂它。所以容器里实际的链路是
>   **`环境变量 → 内置默认`**。第 2 层只在**不用 Docker**（`npm start` 直跑）时存在 —— 那时链路是三层。
>   （想改 Docker 里的配置，就改 compose 的 `environment:` 段，或者临时 `PORT=9000 docker compose up -d`。）
> - **某一层给了值但值不合法 → 当作"这一层没配"，继续往下一层找。** 例：`PORT=abc` → 不认 → 用 `normal.env` 的 `9000` → 都没有就用 `8787`。
>   唯一的例外是 `BIND` 和 `APP_SECRET`：写错了**直接启动失败**（怕你换了密钥才发现，不如吵出来）。
> - **启动日志开头会打印每个值用的是哪一层**，还会逐条写"不认谁、要求是什么、最后用了哪一层的值"。改了不生效时看它即可，不用猜。
> - `normal.env.example` 里就是**部署时要调的那 5 项**：`PORT` / `ADMIN_TRUSTED_PEERS` / `ALLOW_PUBLIC_INTERNET` / `LOG_LEVEL` / `SESSION_TTL_MS`。
>   其中后两项 compose 默认不传，要用就在 `environment:` 里自己加一行（如 `LOG_LEVEL: "debug"`）。
> - 文件名叫 `normal.env` 而不是 `.env` 是**故意的**：不用点开头的隐藏文件名，看得见更放心。

| 变量 | 说明 |
|---|---|
| `APP_SECRET` | **可选**（一般留空）。凭据加密主密钥。留空 = 首次启动自动生成并存到 `data/app-secret.key`（跟库一起备份、一起挂卷，重启不变）。想自己管密钥、或把密钥和数据库分开存放时才填。**换了/丢了它，已保存的上游 apiKey 就解不开**，得重新填一遍 |
| `ADMIN_PASSWORD` | 一般**不用填**：首次启动时会由网页上的「首次设置」页来设。填了的话就用它初始化（容器/脚本化部署省一步）|
| `ACCESS_KEY` | 同上：一般不用填；填了的话"首次启动且库里一个口令都没有"时会拿它建一条 |
| `PORT` / `BIND` | 监听端口与地址。默认 `8787` / 留空（= 所有地址，**双栈**：IPv4 + IPv6 同一端口）。`BIND=0.0.0.0` 同样是"所有地址"。要只监听某个地址就填它（`127.0.0.1` 只本机、`::1` 只 IPv6 环回），写错会启动失败 |
| `DB_PATH` | 数据库位置（容器内默认 `/app/data/app.db`） |
| `ADMIN_TRUSTED_PEERS` | **可选**，一般留空。额外信任的"管理端来源"（反代 / Docker 网桥地址，逗号分隔，支持 CIDR）。默认空 = 只信环回和真正的内网直连（源 IP 被 NAT 抹掉时默认**拒绝**）|
| `ALLOW_PUBLIC_INTERNET` | **只认 `true` / `false`**（大小写不敏感），其他值一律忽略、回落到后台那个开关。`false`（compose 默认）= 公网进不了后台；`true` = 允许公网直接管后台（⚠ 前提：前面有 TLS）；留空 = 不强制。详见「后台交互」一节 |
| `SESSION_TTL_MS` | 后台会话有效期（毫秒），默认 12 小时 |
| `DEFAULT_COOLDOWN_SECONDS` | ~~已废弃~~：等待时长改到后台「设置」页的等待时长表（退避），不再按来源配 |
| `LOG_LEVEL` | `debug` / `info` / `warn` / `error` |

## 上游拒绝策略（每个来源可选）

| 策略 | 行为 |
|---|---|
| `不停用` | 失败也保持可用（**免费来源选它时后台会在策略框旁提示风险**） |
| `倒计时检测` | 失败 → 等一段（见下面的等待时长表）→ **到期自动探测**：成功即恢复可用，失败就换下一段继续等 —— 免费来源推荐 |
| `停用不检测` | 失败直接停用，需人工在后台恢复（付费来源推荐，避免探测花钱） |

> 后台每个来源都有「**立即探测**」按钮，会探测它下面**所有启用的模型**，随时手动验证恢复情况。

## 倒计时检测的等待时长（退避表）

上游**不会告诉我们"什么时候能好"** —— 实测 ModelScope 和 DeepSeek 连限流响应头都不发（`x-ratelimit-*`、`retry-after` 一个都没有）。所以只能靠探测，而"固定等 N 秒"必然是猜：猜小了白打上游、猜大了上游抖一下也要瞎等 5 分钟。

所以改成**一张可编的等待时长表**（后台「设置」页）：

```
第 1 段（默认 15 秒）→ 探一次 → 没恢复
第 2 段（默认 60 秒）→ 探一次 → 没恢复
第 3 段（默认 300 秒）→ 探一次 → 没恢复 → 之后一直用 300 秒（最后一段带"+ 后续"）
```

- **前几段短**：上游抖动几秒就好的情况，15 秒就能探回来（原来要等 5 分钟）
- **最后一段长**：额度类只能慢慢等，别把请求打空（和原来一样的节奏）
- **探测成功就恢复可用**，等待表从头再来
- **冷却期间手点「测试」也算一次失败 → 表往前推一段**（不会把倒计时打回第一段）。
  例：正在等 15 秒时点测试 → 直接变成等 60 秒；在最后一段点测试 → 原地重新计时。
- 加几段、删几段都行（后台那个「＋ 再加一段 / 删除最后一段」）；上限 20 段
- 429 带 `Retry-After` 时**取它和当前段的较大值** —— 上游明确说了要等多久，就按它说的等

**有些错不值得探测，直接转「需人工」**：上游回 **400/422**（例如 `Invalid model id: xxx`、参数被拒）这类**探测一万次也不会好**的错 —— 那是配置写错了，得人去改。这种错**不进冷却、不排探测**，状态直接变「故障（需人工）」，原因里带上游原文。同理，**404（上游没有这个模型）**也是：`All` 会继续换源，但这个模型本身转「需人工」。

**探测次数上限**（全局设置「倒计时检测次数上限」，默认 10；0 = 一直探测）：某个模型**连续探测失败**到上限后，就停止自动探测、转成「故障（需人工）」，不再对这个修不好的模型继续发请求。探测成功或你手动「恢复可用」会把计数清零。
估算：**把等待表按次数累加 ≈ 放弃前的最长等待时间**（默认 15+60+300×8 ≈ 41 分钟）。如果某个源的额度是"每天刷新"的，想让它能一直等到刷新，就把上限调大（如 288 ≈ 24 小时）或者设 0。

### 状态是"按模型"记的，不是"按来源"

同一个来源下不同模型的额度/限流往往各自独立（典型：ModelScope 上今天这个模型用完了、同家另一个还正常）。所以：

- 冷却 / 停用 / 恢复都是 **(来源, 模型)** 级的：某个模型挂了只冷却它自己，同家别的模型照常使用；
- 「All模型顺序」页里每个模型行显示的**是它自己的状态**；
- 提供商列表显示的是**聚合结果**，例如 `可用` + `1/2 个模型可用`；只有一个模型能用，这个来源就算"可用"；
- 「恢复可用 / 手动停用」这类来源级操作，会作用到该来源下的所有模型。

## 后台交互（几个约定）

- 「**添加提供商**」是一个按钮，点开是**弹层表单**，右下角「取消 / 添加」；编辑也是同一个弹层（「保存」）。
- 提供商列表可以直接**拖拽排序**（免费组内、付费组内各自拖，松手即保存）。
- 「设置」页里两个开关各占一行，不挤在一起。
- 后台一共 7 个页签：**主页**（概览 + 最近调用）、**All模型顺序**（拖拽决定 `All` 的选源顺序）、**模型组**、**提供商**、**密码**、**日志**、**设置**。
- **主页那排卡片看的是"今天的情况"**：今日请求数 / 失败次数、免费 token 用量、付费 token 用量（各带输入/输出拆分）、可用模型数。
  - **"今日"的零点由后台「设置」页的「时区（UTC 偏移小时）」决定**，默认 `0` = UTC（这时卡片上不加任何后缀）；填 `8` 就会显示成 `今日请求 · UTC+8`。**不看操作系统时区、也不看 `TZ`**（很多 Linux 装完就是 UTC，用户并没意识到，跟着系统走会得到莫名其妙的日子）。
  - 同一个零点**也管 `rpd`/`tpd` 日额度的重置时刻** —— 两处必须一致，否则"今日请求数"和"额度什么时候回来"会对不上。
  - token 是 `输入 + 输出` 的总和，**把今天所有请求全加起来**：成功的、失败的（上游给了部分用量的）、后台「测试」和倒计时探测的，全都算（探测也是真打上游，CF 那种按 token 计费的平台该算就得算）。
  - **token 数字超过 1000 就写成紧凑形式**：`46447` → `46.4k`、`6789372` → `6.8m`（表格和卡片都这样，鼠标悬停能看到精确数字）。
  - **失败次数**不含"客户端自己取消"（`client_abort`），否则你每打断一次流就 +1。
  - **可用模型**：`可用 / 总数`。冷却中、额度用尽、本地限速中的**都算可用**（它们会自己恢复）；只有「故障（需人工）」和手动禁用的不算，副行里分开列出来。
  - 免费 / 付费怎么分：按写日志那一刻记下的"这次命中的是不是付费来源"，而不是事后回查来源现在的属性 —— 来源后来被改或删掉，历史统计也不该跟着变。
- **「模型组」页**：最上面固定一行「＋ 添加模型组」（组多了也不会被挤下去）；下面每组一行 `[组名输入框][展开箭头]`——**组名失焦即存，没有"保存"按钮**，点箭头展开后能加/删模型，组内也支持拖拽排序。
- 主页「最近调用」和「日志」页把名字拆成两列看：**请求模型**只显示模型名（填 `All` / 模型组的就显示 `All(实际用的模型)`），**来源**显示 `Free/来源id` 或 `Pay/来源id`。点「测试」产生的记录也一样，方便对照。
- 这两张表都有 **`token（入/出）`** 一列，写的是一次请求自己的用量（`46.4k / 1.2k` 这种紧凑写法，悬停看精确值）。**上游没返回 `usage` 时显示 `-` 而不是 `0`** —— `0` 是"真的一颗都没用"，`-` 是"上游没说"，排查问题时这两件事完全不一样。
- 「All模型顺序」页模型表的列：**只有「模型」列自适应**（长了在自己这列换行），其余列固定宽度且**靠右对齐**；免费表与付费表共用同一套列宽，所以两段永远对齐。
- **管理后台默认只允许本机/内网来源**（设置项 `admin_local_only`，默认开）：后台和 `/v1` 是同一个端口，把 API 开放出去很容易顺带把后台也端出去，所以默认挡住。**公网 IPv4 和公网 IPv6 一视同仁**（都 403），本机/内网包含 `127.0.0.1`、`::1`、`10./192.168./172.16-31.`、`fc00::/7`、`fe80::/10`，以及双栈下 IPv4 客户端的 `::ffff:x.x.x.x` 形式。公网来源打开 `/admin` 会看到一句「管理端只允许从本机或内网访问（你在 x.x.x.x）」，`/v1/*` 完全不受影响。
  - 要在外网管后台，**最省事的是环境变量 `ALLOW_PUBLIC_INTERNET`**：
    - **只认 `true` / `false`**（大小写不敏感）。写别的（`yes`、`1`、乱写）**等于没写** —— 会被忽略并回落到下面那个开关。
    - `false`（compose 里的默认）= 强制不允许公网访问后台。
    - `true` = 允许公网直接管后台。⚠ **前提是前面有 TLS**（反代 / Cloudflare Tunnel），否则管理口令和会话 cookie 会明文过网。
    - 留空 = 不强制，交给后台「设置」页的「管理端限内网」开关决定。
    - 认了 `true`/`false` 时，设置页那个开关会**置灰**（改它不生效）；启动日志会明确写出：认了哪个值 / 没认（会告诉你原本写的是什么）/ 用了什么默认。
  - 不想开公网也可以用 **SSH 隧道**：`ssh -L 8787:127.0.0.1:8787 user@host`，然后开 `http://localhost:8787/admin`。

## 安全说明

- 上游 apiKey：`libsodium` secretbox 认证加密后入库；界面只回显掩码。
- **下游访问口令**：只存**能还原的那一份** —— `key_enc`（libsodium 密文）。校验 = 解密出来做常量时间比对（比哈希校验快得多），后台「密码」页也靠它显示掩码 / 一键复制。明文不进 `.env`、也不在库里。
  - 用户裁定 2026-09-12：既然密文已经在库里，那份不可还原的 argon2 哈希（`key_hash`）就不再提供额外保护，只带来"两套真相"，已删除（migration `0010`）。
  - 代价如实说：**库 + `APP_SECRET` 一起泄露 = 下游口令直接暴露**。跟过去"明文写在 `.env` 里"同一风险等级，但比那时可控（密钥可以单独注入）。想更严就用一个有强度、不跟库放一起的主密钥。
- **管理密码**：只存 `argon2` 哈希（不可逆），所以界面上显示不出明文、也复制不出来 —— 只能"改"。（这条**故意**不可还原，和下游口令的要求正好相反。）
- 主密钥：环境变量 `APP_SECRET` 或数据目录里的 `app-secret.key`（缺省自动生成）。**丢了就解不开已存的 key**（包括上面那份访问口令密文，此时界面会提示"不可显示、请重新生成"）。
- 已经用测试断言保证：**数据库文件里搜不到任何明文 key 或口令**（加了密文之后依然如此）。

**2026-09-13 一轮外部审计后的加固**（逐条都有测试或可复现验证）：

| 项 | 做了什么 |
|---|---|
| 首次设置被跨站劫持（严重，已实证） | 后台所有写操作加同源校验（`Sec-Fetch-Site` / `Origin`）；curl 与客户端脚本不受影响。测试 M6-8 |
| 源 IP 被 NAT/代理抹掉时管理端闸失效 | 判定改成 fail-closed：带 `X-Forwarded-For`、或对端是 Docker 网桥/slirp 网关（172.17.0.1 / 10.0.2.2）→ 默认拒；要放就显式配 `ADMIN_TRUSTED_PEERS`。测试 M8-8 |
| 登录可无限爆破 | 按来源 IP 指数退避锁定（5 次失败起锁 30 秒、翻倍到 1 小时）+ 全局兜底；锁定期正确密码也先挡。测试 M6-10 |
| 改密码踢不掉已登录会话 | 库里记"改密时刻"，比它早签发的会话立即失效；`reset-credentials` 同样生效。测试 M6-9 |
| 缺安全响应头 | 加 `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy`；后台接口一律 `Cache-Control: no-store`；`/admin` 上 CSP（`script-src 'self'`，内联脚本已外置成 `/boot.js`） |
| 上游可 302 到内网/元数据地址（SSRF） | 上游 fetch 一律 `redirect: 'error'`；`baseUrl` 拒绝链路本地/元数据地址（内网自建推理服务仍允许） |
| 容器以 root 运行、无限制 | 镜像内非 root（uid 10001）+ compose 加 `no-new-privileges`、`cap_drop: ALL`、内存/PID 上限。**注意**：宿主机 `./data` 要 `chown -R 10001:10001` |
| 依赖漏洞（qs 两条 moderate） | `overrides.qs` 提到 `^6.16.0`；`npm audit` 现在 0 vulnerabilities；构建阶段不再 `--no-audit` |
| 前端埋着 innerHTML 通道 | 直接删掉 `h()` 的 `{ html }` 分支（全仓无调用点） |
| 口令指纹被写进日志和跳转 URL | 不再记录/回显指纹，只留长度这类形态信息 |
| `proxyUrl` 是死配置 | 不再接受也不再返回（字段存了但从不生效，等于骗人） |
| 回滚能一把清空数据库 | `npm run migrate:rollback` 换成安全包装：必须 `--yes`，且**先自动备份 data/** 才回滚 |
| 死配置（`production` 从不生效） | `src/db.js` 的非测试分支改用 `production` 配置 |

还有几条**没做**，如实记着：`trust proxy: true` 让日志里的 `ip` 可被伪造（认证判定用的是 TCP 对端，这点没问题，但别把日志当溯源证据）；CSP 只在本机验证到"页面仍能加载"，**没有在真浏览器里逐项测过**；`git` 历史里有一个已删除的 `form-login.txt`（里面有十几小时前就过期的 session cookie）—— 不重写历史（那会打乱所有提交号），确认已过期，**不再需要做任何事**；Dockerfile 的基础镜像是可变 tag、`npm ci` 在构建阶段仍以 root 跑安装脚本（原生模块需要它），属于已接受的构建期风险。
